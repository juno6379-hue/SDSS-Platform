# 2026-10-16 후속 병렬 개발 기록

## 1. 사용자 지시와 작업 분담

“각 에이전트별로 남은 작업을 진행” 지시에 따라 기존 세 에이전트를 재개했다. 개발 순서는 수집 제어·실제 자료 확인 → 학습 전 충분성/분할 검사 → 정합 감사 → 조건 충족 시 학습 → 화면·API 통합 검증이다. 서로 독립적인 구현은 병렬로 진행하되 데이터 부족을 학습 실행으로 덮지 않는다.

## 2. 추가 수집 예산의 분리

기존2GiB 예제 예산 원장은2,147,483,646bytes이며 변경·삭제·임의 환불하지 않는다. 문서04의2GiB는 예제 개발 예산으로 사용자 지정 절대 한도가 아니다. 사용자의 자료 확보·후속 작업 지시에 따라 별도32MiB 보충 실험을 계획했다. 신규 상한33,554,432bytes, 과거 예약 포함 종합 상한2,181,038,078bytes다. 실제 수신량과 예약량을 구분하고, 첫429 발생 시 중단한다. 이 작업은 제한을 피하기 위해 계정·프록시를 바꾸는 방식으로 진행하지 않는다.

신규 보관 경로는 `data/first-group-recovery32/`이며 Banten/West Java2021의 품질 좋은 검증·시험 창을 우선한다. 32MiB만으로1,000개 적격패치를 확보했다고 가정하지 않는다. 실행 여부와 확보량은 해당 보고서로 확정한다.

## 3. 읽기 전용 수집 현황 API

`backend/app/collection_status.py`와 GET `/api/data/collection-status`를 추가했다. 보고서 목록은 데이터 루트의 `first-group*/**/annual-window-report.json`에서 읽으며 현재36개 주·연도 셀로 집계한다. 최근 실패가 과거 성공한 영상·라벨 재고를 지우지 않도록 두 상태를 분리했다. 데이터 루트 밖 파일은 재고로 인정하지 않으며 원격 오류 원문/서명 query를 반환하지 않는다. 보고서가 저장 중이거나 없으면 unknown으로 처리한다.

전체 B04는 전체 단일밴드로 구분하며 파일 존재·바이트·기록된 해시를 반환한다. 매 요청마다221MB 원본을 다시 해시하지 않으므로 `hash_verified_now=false`를 명시한다. 품질 적격은 수집 보고서 해시가 별도 품질 감사와 일치할 때만 표시한다.

학습 준비 보고서는 `data/first-group/training-readiness.json`을 읽는다. 준비 완료 선언 시 입력 manifest와 파일 해시를 검증하며 변경/미존재 시 `stale_or_missing`으로 준비 상태를 취소한다. 해시는 경로·mtime/ctime·크기를 키로 캐시하고 학습 실행 시 ML runner가 다시 검증한다. 독립 정확도 검증 여부와 개발 학습 준비 여부는 별도다.

API 모듈6개 시험은0.560초에 통과했다. 과거 성공 뒤429, 외부 경로·미존재 파일, 미완성 JSON, 감사 해시, 준비 완료 이후 입력 변경을 검증했다. API11개 시험도0.917초에 통과했으며 새 조회의 인증과 빈 상태를 확인했다. 최종 통합 시험 전 중간 결과다.

## 4. 실제 화면 중간 확인

Vite 개발 서버를 실제 frontend 경로에서 재시작했다. 브라우저에서36목표/6영상/6라벨/3품질 적격, 과거 연차 실행의42927/예산8/장면없음1/완료창0, B04 전체 단일밴드10980×10980을 확인했다. 이는 보충 수집 실행 이전의 실제 재고다. 화면 검증 중 외부 검색·수집 버튼을 실행하지 않았다.

## 5. 동일 예산의 로컬 인계와 실제 다운로드 성공

하위 에이전트 환경의 최초 접속은 DNS11001로 실패했고 COG/메타데이터 수신·차감이 모두0이었다. HTTP 서버 응답이 없어 과거429의 재발로 판정하지 않았다. 이 결과를 `dns-attempt-result.json`과 해시로 보존하고, DNS0바이트·HTTP상태없음·기존원장불변 조건에서만 허용되는1회 인계로 같은32MiB 실험을 루트 로컬 환경에서 실행했다. 새 예산을 추가하거나 과거 예약을 환불하지 않았다. 사용 명령은 다음과 같다.

```powershell
$env:PYTHONPATH='.runtime;backend'
$env:PYTHONIOENCODING='utf-8'
python scripts/collect_recovery_validation.py --execute --handoff-after-dns
```

실제 실행은 exit0이다. 서버 연결/STAC 검색/6밴드 픽셀 다운로드/WorldCover 원본 및 정합 라벨 저장이 모두 성공했다. 동시성1·요청 간격2초로 실행했으며 이번429는0건이다. 첫 후보의 중심점이 해당 COG 밖이어서 거부한 기록은 그대로 남겼고, 다른 적격 후보를 채택했다.

|주|선택 영상 ID|촬영 UTC|장면 구름률|최종 유효 라벨 비율|
|---|---|---|---:|---:|
|Banten|S2B_MSIL2A_20210817T025549_R032_T48MXT_20210817T112405|2021-08-17 02:55:49.024|5.46396%|99.603271%|
|West Java|S2B_MSIL2A_20210827T025539_R032_T48MYT_20210827T134055|2021-08-27 02:55:39.024|7.89399%|99.963379%|

각각256×256의 **B02/B03/B04/B08/B11/B12** stack과 WorldCover2021 라벨이다. 20m SWIR의 원본 crop도 보존하고 공통10m stack에는 bilinear, WC/SCL에는 nearest를 사용했다. raw 밴드·raw WC/SCL·별도 quality mask·STAC JSON·제품 XML·해시를 함께 보존했다. 전체 원격 밴드 파일 다운로드가 아닌 작은 원본 픽셀 창이다. 전체 B04221,758,050bytes 파일의 기존 증거와 구분한다.

COG 실제 읽은 본문14,090,240bytes와 메타데이터262,573bytes로 신규 차감14,352,813bytes다. HTTP헤더·TLS오버헤드까지 포함한 총 네트워크 사용량이라는 뜻은 아니다. 과거 예약 포함 종합 차감상한2,161,836,459bytes는 계획 상한2,181,038,078bytes 이내다. 기존 실패 원장 불변을 확인했다. 최종 `run-result.json`과 `annual-window-report.json`을 보존했다. 추가 반복 수집은 실행하지 않았다.

## 6. 제품 보정 근거와 원본 픽셀 재현

두 제품의 원본 XML을 받고 STAC의 제품 URI와 일치를 검증했다. 실제 BOA_QUANTIFICATION_VALUE10000, 처리 baseline03.00에 맞는 offset0 근거로 각6밴드의 scale0.0001/offset0을 `calibration.json`에 기록했다. 원본 image.tif는 DN을 그대로 보존하며 검증된 변환은 향후 학습 입력에서 적용한다. `reflectance_conversion_verified=false` 및 `applied_to_image=false`는 원본 파일을 아직 반사도로 변환하지 않았다는 표시이며 `calibration.metadata_verified=true`와 구분한다.

제품별 변환식·DN0 NoData·PB04 이후 밴드 offset 도입은 [Copernicus SentiWiki](https://sentiwiki.copernicus.eu/web/s2-products)의 Level-2A 규칙과 대조했다. 새 두 제품의 XML 근거가 과거3패치의 미저장 메타데이터를 소급 검증하는 것은 아니다.

`data/audits/recovery32-alignment.json`은 실제 새2쌍의 정합PASS2, 원본 재현PASS2다. EPSG32748 공통10m격자를 확인하고 raw WorldCover EPSG4326 512×512를 최근린 재투영한 뒤 품질 제외를 적용한 결과가 저장 라벨과 전체 픽셀 일치했다. raw SCL로 독립 계산한 quality mask도 전체 픽셀 일치했다. WC 불일치0, SCL 불일치0이며 제외 라벨은 Banten260/WestJava24픽셀이다. 과거 원본 미보관9쌍의 최초 재투영 재현 미검증 한계는 계속 유지한다.

## 7. 최신 충분성 판정과 모델 상태

`data/first-group/quality-audit-current.json`은 기존RGB6창+신규6밴드2창의8개 실제 창, 고유 주·연도6셀/36셀, 품질 적격5패치를 기록했다. 혼합 재고의 적격 분할은 train3/validation1/test1이다. API는 동일 보고서·같은 행의 감사 근거를 대조해 현재 선택한6셀 중 품질 적격5셀을 표시한다. 이 값은6밴드 학습 적격5개라는 뜻이 아니다.

정식6밴드 실험의 `training-readiness.json`은 새6밴드 보고서만 입력으로 평가했다. 실제 계약 적격은 **2패치(train0/validation1/test1)**, 미확보 주·연도34셀, 차단 사유15개이며 `ready_for_training=false`다. 1,000패치 및 클래스·지역·시기 대표성 기준을 충족하지 않는다. 2020/2022~2025 라벨이 추가 확보됐다고 표시하지 않았다.

`scripts/run_experiment.py`와 실자료 `train_model`에 같은 gate를 연결했다. API 직접 호출이나 과거 baseline runner로 검사 없이 소규모 실자료를 재학습하는 경로도 차단한다. 새 제품별 정규화·밴드 순서·품질 마스크·시기·원본 그룹별 분할·train만의 class weights를 검사하며 예측이 단일 클래스에 붕괴하면 출력 다양성 검사에서 거부한다. 이 검사는 정확도 인수 기준이 아니다. 독립 참조 없이 수행할 수 있는 개발 학습은 의사라벨 일치도 실험으로만 표시한다.

실제 재학습은0회이며 기존3patch/3epoch checkpoint와 보고서 해시는 변하지 않았다. 새 소스2창/영상·라벨4파일 해시를 검증하여 카탈로그 `first-group-recovery32-source-v1`로 등록했다. `training_ready=false`를 유지한다.

## 8. 통합 검증과 남은 작업

최종 통합 unittest **107개/28.065초/exit0**를 확인했다. 이후 최신 품질 감사 연결만 보완하여 해당 수집 현황7개 시험을0.674초에 다시 통과했다. 외부 서비스 성공의 증거는 합성 시험이 아니라 위 실제 수집 결과다. 프런트엔드는 새2창의6밴드·마스크·라벨과 최신4290을 실제 브라우저에서 확인했다. 전체 UAT·운영 배포·독립 정확도 검증을 완료한 것은 아니다.

최종 프런트엔드 build는 TypeScript/Vite36modules,24.63초,exit0이며 MapLibre 포함 번들크기 경고는 남는다. API 최종 재시작 후 실제 HTTP 응답을 `data/audits/collection-status-response.json`으로 보존했다. 브라우저 재조회에서도6영상셀/6라벨셀/5품질셀,6밴드 학습 계약 최소1000·train0/val1/test1·차단15건·최신수집2창/4290을 확인했다. 각 에이전트의 해당 단계 코드 변경은 완료했으며 데이터 부족으로 차단된 학습을 완료한 것으로 표시하지 않는다.

남은 데이터 작업은 다른4주의6밴드 train 자료, 연차별 원본과 해당 시기 참조,1,000~3,000개 대표성 있는 적격패치 확보다. 정식 재학습과 독립 정확도 평가는 그 근거가 마련된 뒤 진행한다. 이번32MiB 실험은 네트워크 경로 복구와 검증/시험 지역의 고품질 소규모 자료 확보까지 확인한 체크포인트다.
