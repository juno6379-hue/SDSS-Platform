## 1. 개발 순서와 완료 범위

1. AOI·날짜·구름량·검색량을 공통 검증하도록 구현하였다. AOI는 EPSG:4326의 `[west, south, east, north]`이며 날짜변경선 교차는 두 AOI로 분할한다. 숫자형 boolean, NaN/Infinity, 역전 날짜, 잘못된 날짜를 거부한다.
2. Element 84 Earth Search STAC `/v1/search`를 표준 라이브러리 urllib로 호출한다. Sentinel-2 L2A와 Landsat Collection 2 L2를 지원하며 검색 조건을 응답에 남긴다. GeoTIFF 자산만 선별하고 미리보기 JPEG는 제외한다. 페이지당 최대 100개이며 후속 페이지 존재를 `truncated`로 알린다. 자동 전체 순회는 하지 않는다.
3. 승인된 공개 데이터 호스트의 HTTPS 자산만 다운로드한다. 허용 호스트, 리다이렉트, 파일명, 데이터 루트 내 실제 경로를 검증한다. URL/파일명을 통한 내부망 접근과 상위 디렉터리 탈출을 거부한다. 외부 경로에서 수동 파일을 가져오는 기능은 제공하지 않으므로 관리자가 먼저 데이터 루트로 파일을 배치한다.
4. 기본 512 MiB/요청, 최대 2 GiB/요청으로 본문 크기를 제한한다. Content-Length 사전 확인과 스트림 누적 검사를 함께 수행한다. 기본 재시도 2회, 최대 5회이며 네트워크 오류에 지수 간격을 적용한다.
5. URL 해시별 `.part`에 저장하며 ETag 또는 Last-Modified와 If-Range가 있을 때만 재개한다. 서버가 Range를 무시하면 덮어쓰기로 재시작한다. Content-Range 시작 오프셋을 확인한다. 완료 후 SHA256을 계산하고 선택적인 기대 해시를 대조한다. 내용 해시가 같은 기존 파일을 재사용한다.
6. 파일별 출처, 바이트 수, SHA256, 라이선스 선언, UTC 기록 시각을 JSON manifest에 기록한다. 서명 URL query는 manifest에 남기지 않는다. 라이선스를 제공받아도 자동 법률 검증으로 취급하지 않으며 `license_verified=false`로 명시한다.
7. 수동 GeoTIFF 등록 시 실제 rasterio 열기로 CRS·bounds·격자·밴드 수·dtype·NoData를 수집한다. 단순 확장자만 보고 성공으로 처리하지 않는다. 선택 의존성 미설치 시 명확한 RuntimeError로 종료한다.
8. ESA WorldCover 2020 v100/2021 v200의 AOI 교차 3×3도 Map 타일 URL을 계획한다. 최대 100개 후보를 생성하며 `availability_checked=false`, `executed=false`를 반환한다. 해양 후보 등은 존재하지 않을 수 있다. 각 타일의 URL/filename/license를 다운로드 함수에 전달하여 실제 파일을 수집한다.
9. Dynamic World `GOOGLE/DYNAMICWORLD/V1`의 공식 클래스 순서 9개 확률 밴드를 기간 평균한 Float GeoTIFF 내보내기 어댑터를 구현한다. 이 평균 확률의 argmax는 시계열 label 최빈값과 다를 수 있다. 초기 label mode 1밴드 방식은 ML의 confidence threshold 계약과 맞지 않아 교체했다. 기본은 계획 생성이며 `execute=true`일 때만 SDK·프로젝트·인증을 확인하고 Drive export 작업을 제출한다. `submitted`는 완료를 의미하지 않으며 `completed=false`와 task_id를 반환한다. 실제 EE 실행은 미검증이다.
10. 범주형 label을 참조 래스터와 동일한 CRS·transform·크기로 최근린 정렬하는 함수를 구현했다. 명시적 NoData가 없으면 겹치지 않는 영역을 실제 클래스 0으로 오염시키지 않도록 거부한다.

## 2. 공개 함수 계약

```python
from pathlib import Path
from app.data.service import search_stac, download_asset, register_local, worldcover_plan, dynamic_world_export

query = {"bbox": [106, -7, 107, -6], "start_date": "2024-01-01", "end_date": "2024-02-01",
         "collection": "sentinel-2-l2a", "cloud_cover": 20, "limit": 5}
scenes = search_stac(query)  # 실제 네트워크 호출
plan = worldcover_plan({"bbox": query["bbox"], "year": 2021})  # 네트워크 호출 없음
# 실제 다운로드: download_asset(plan["tiles"][0], Path("data"))
# 수동 등록: register_local({"path": "manual/scene.tif", "license": "..."}, Path("data"))
# EE 계획: dynamic_world_export(query)
# EE 제출: dynamic_world_export({**query, "execute": True, "project": "등록된 프로젝트"})
```

STAC 응답 `items[].assets`에서 밴드 키(red, green, blue, nir 등)를 선택한 뒤 href를 download_asset의 url로 전달한다. 카탈로그별 밴드 이름을 고정 가정하지 않는다. `ValueError`는 입력/무결성 오류, `RuntimeError`는 외부 시스템/선택 의존성 실패를 나타내며 API 계층에서 상태 코드로 변환한다.

## 3. 검증 방법과 실데이터 경계

`python -m unittest discover -s tests -p "test_data*.py" -v`로 테스트한다. 테스트는 외부 네트워크를 mock 처리한다. 검색 요청 필터·자산 선택, AOI/날짜 검증, 호스트/경로 차단, 바이트 제한, SHA256 불일치, 중복 재사용, Range 재개/무시, 재시도, WorldCover 격자 경계, EE 계획/인증 실패를 검증한다. rasterio/numpy가 설치되면 임시 소형 GeoTIFF의 등록·최근린 정렬도 확인한다. 임시 GeoTIFF는 테스트 입력이며 실데이터 분석 결과로 제시하지 않는다.

초기 mock 검증 시점에는 실제 위성자료를 확보하지 않았다. 이후 2026-10-16까지 승인된 PC 접근으로 실제 2023 B04 64×64 창과 2021년 3지역 RGB256×256/SCL/정합 WorldCover를 확보했다. 상세 증거는 문서10 및 `data/baseline2021/annual-window-report.json`에 있다. Earth Engine 인증/export 완료와 충분한 연차 학습자료는 계속 미검증이다.

## 4. 운영 제한과 후속 개발 순서

1. 현재 다운로드는 동기 작업이다. 대형 수집은 작업 큐·진행 상태·취소와 전역 디스크 할당량을 추가해야 한다. 동일 URL 동시 다운로드는 외부 작업 큐에서 직렬화해야 한다. 서로 다른 URL 파일/manifest는 분리되어 있다.
2. Landsat 자산은 USGS 정책에 따라 로그인·추가 동의가 필요할 수 있다. 인증을 우회하거나 비밀정보를 코드에 넣지 않는다. 허용 호스트 변경은 운영자가 확인 후 코드 리뷰로 반영한다.
3. 등록 후 장면별 반사율 보정, 구름 마스크, 밴드 정합, 스케일·오프셋 적용을 데이터 전처리 계층에서 수행해야 한다. 수집 파일을 그대로 학습 가능한 배열이라고 주장하지 않는다.
4. WorldCover와 Dynamic World는 서로 다른 클래스 체계다. 클래스 매핑/NoData 정책을 별도로 확정한 후 정렬한다. WorldCover 연도 간 알고리즘 버전 차이가 있으므로 단순 차분을 실제 토지피복 변화 정답으로 취급하지 않는다.
5. 실제 자산의 샘플 다운로드와 라이선스/attribution 확인 → AOI 클리핑 → 클라우드 마스크 → 클래스 매핑/최근린 정렬 → 데이터 분할 누수 검사 → 학습 순으로 진행한다. EE 작업은 task_id로 원격 상태를 별도 확인해야 한다.

## 6. 충분한 자료 확보 기준과 병렬 개발 추가분

초기 T1/T2 수집 단계에서 서부 자바·중부 자바·남부 술라웨시의 연구 후보 3개 AOI를 제시했다. 이는 임의의 후보 좌표이며 확정 사업/행정 경계가 아니다. 실제 경계는 사업 자료/발주처와 대조해야 한다. 전장면 호환 경로는 blue/green/red/nir/swir16/swir22 자산을 갖춘 최소6개 장면을 목표로 했다. 현재 기본 설정은 아래7절의 연차별 제한 창 계획으로 갱신되었다.

`scripts/collect_samples.py` 기본 실행은 **계획 전용**이다. `--execute`를 명시한 인터넷 가능 로컬에서만 STAC 검색·실파일 다운로드를 수행한다. 전체 다운로드 디스크 예산 기본 2 GiB, 자산별 256 MiB를 강제하며 완료파일과 부분파일을 모두 집계한다. 이 기본 예산으로 여섯 다중밴드 장면 전체가 충분히 확보된다고 보장하지 않는다. 원본 크기에 따라 일찍 중단될 수 있고 실행 보고서에 목표 미달을 남긴다. 자산 실패가 다른 AOI 실행 이력을 지우지 않는다.

출력 `collection-state.json`으로 성공 자산을 추적하며 재실행 시 SHA256과 경로를 확인한 기존 파일은 재다운로드하지 않는다. 설정 해시가 다르면 같은 실행 상태를 섞지 않도록 별도 출력 경로를 요구한다. `collection-history.jsonl`은 시작/성공/실패/검증 후 건너뛰기 이력을 보존한다. 누적 예산은 다운로드 파일 기준이며 작은 manifest/로그 메타데이터까지 포함하는 전체 파일시스템 할당량은 아니다.

`collection-plan.json`/`collection-report.json`은 AOI·시기별 검색·밴드 확보 결과, 장면 bbox 기준 기하학적 커버리지 상한, 유효 픽셀 비율, 클래스 커버리지, 검증 패치 수를 분리한다. bbox 커버리지는 실제 구름 없는 픽셀 커버리지가 아니다. 유효 픽셀과 클래스는 검증 전 `null`, 패치는 0으로 기록한다. **1000~3000 패치는 목표이며 원본 해상도·클라우드 마스크·라벨 정합·공간분할 검증 전 예상 확보량으로 주장하지 않는다.**

ESA WorldCover 2021은 라벨 후보로 계획/선택 다운로드되지만 T1=2020/T2=2024와 시기가 일치하지 않는다. 다운로드 자체로 학습 라벨 준비 완료라고 표시하지 않는다. 이 시기 차이를 해결하거나 동시기 지상정답/검증자료를 확보한 후 클래스 매핑/정렬/구름 마스크/독립 공간검증을 완료해야 `learning_ready` 판단을 추가할 수 있다. 현재 수집 스크립트는 성공한 밴드 수와 무관하게 `learning_ready=false`를 유지한다.

초기 Earth Search DNS 실패 및 재실행 거절 후 그 승인 경로를 우회하지 않았다. 이후 사용자가 별도로 요청하고 승인한 PC 접근 범위에서 실제 자료를 확보했다. 최신 실제 확보는 아래 연차 추가 기록을 따른다.

```powershell
# 네트워크 호출 없는 후보/예산/누락 요건 계획 생성
python scripts/collect_samples.py

# 인터넷 가능한 로컬에서 실제 수집 (예산과 경계 설정을 확인한 후 실행)
python scripts/collect_samples.py --execute --output data/collection

# 동일 설정/출력으로 재실행하면 SHA256 검증한 성공 자산은 건너뛴다
python scripts/collect_samples.py --execute --output data/collection
```

## 7. 연차별 수집 계획과 실제 2021년 소규모 확보 (2026-10-16)

현재 기본 설정은 `collection_mode=bounded_windows`, PC 카탈로그, 2020~2025년 동일 6~9월 계절, 연구 후보 3 AOI로 **18개 AOI-year 셀**이다. 이전 T1/T2 전장면 수집은 호환 경로로 유지되며 `years`가 있으면 연차 설정이 우선한다. 2026년을 추가하면 해당 연도는 `incomplete_year=true`로 표시한다. 각 연도의 인접 연도 쌍과 최초 기준 연도 대비 쌍을 보고한다.

기본 소규모 수집은 각 셀의 중심 256×256 RGB 창 한 개다. 이 설계의 명목상 최대 256×256 패치는 18개이므로 1000개 확보를 주장할 수 없다. 보고서의 8×8 격자·간격 2560 m 확장 계획은 총 1152개 **후보**의 상한이며 아직 실행하지 않았다. 구름·수역·희소 클래스·중복·AOI 경계·동일 원장면/그룹 누수 검사를 거쳐 유효 패치가 줄 수 있다. 충분한 패치 수량은 quality 검증 후에만 확정한다.

`--years 2021 --output data/baseline2021 --execute` 실제 실행으로 세 독립 연구 지역의 RGB 창과 SCL, WorldCover2021 정합 라벨을 확보했다. HTTP 본문 합계 8,912,896 B였다. RGB는 blue/green/red 원본 DN 순서이며, 라벨은 원래 ESA 클래스 코드다. RGB의 NoData와 SCL의 nodata/saturated/shadow/cloud/cirrus/snow를 제외한 뒤 최근린 WorldCover 라벨에 동일 마스크를 적용했다.

| 연구 후보 | 촬영일 | 장면 구름피복률 | 유효 픽셀 비율 | 표본에 존재하는 ESA 클래스 |
|---|---|---:|---:|---|
| west_java_candidate | 2021-09-21 | 16.047392% | 95.6299% | 10,30,40,50,60 |
| central_java_candidate | 2021-09-30 | 0.586501% | 99.6399% | 10,30,40,50,60 |
| south_sulawesi_candidate | 2021-09-26 | 0.367613% | 98.2239% | 10,30,40,50,60,80,90 |

이 결과는 약지도 라벨 기반 소규모 실행 검증 입력이다. 지상 정답의 독립 검증이나 정확도 목표 달성을 의미하지 않는다. S2 2021 영상도 재처리 가능하므로 연도만으로 scale=0.0001/offset=0이라고 확정하지 않는다. 초기 실제 수집 프로세스는 asset의 raster:bands를 보존하지 않아 원본 DN의 물리 반사도 변환이 아직 미검증이다. 이후 검색 API는 원본 item properties 및 asset raster:bands/eo:bands를 보존하도록 수정했다.

2020/2021은 해당 연도 ESA WorldCover를 약지도 후보로 사용한다. 2022~2025는 Dynamic World 연차 확률 내보내기 계획만 제공하며 실행하지 않았다. 실제 연차 18개 셀 메타데이터 추가 조회는 별도 실행 요청이 거절되었으므로 18개 전체를 검색/다운로드한 것으로 표시하지 않는다.

이어 승인된 단일 원본 파일 검증으로 서부 자바2021 장면의 B04 전체 파일 221,758,050 B를 확보했다. ## 8. First Group 6개 주의 실제 경계와 연차 수집 (2026-10-16)

1. [geoBoundaries 공식 API 문서](https://www.geoboundaries.org/api.html)를 확인하고 `https://www.geoboundaries.org/api/current/gbOpen/IDN/ADM1/` 메타데이터를 실제 수신했다. 메타데이터의 simplifiedGeometryGeoJSON 링크를 받아 3,397,843 B, 34개 ADM1 feature를 보존했다. 최대32 MiB 제한, HTTPS 및 공식 geoBoundaries/GitHub 호스트 검증을 적용했다.
2. 원본 shapeName을 인도네시아어/영어 별칭과 대조하여 사용자 지정6개 주를 정확히 하나씩 선택했다. `data/first-group-boundaries/selected-six.geojson`은 이6개 공개 참조 경계다. 원본/선택결과 SHA256과 출처는 `boundary-manifest.json`에 있다.
3. 이번 IDN ADM1의 원본 메타데이터는 **boundaryYearRepresented=2017, source=OpenStreetMap/Wambacher, license=Open Data Commons Open Database License 1.0**이다. 일반 gbOpen 설명의 CC BY 관련 문구를 이 파일의 실제 라이선스로 대체하지 않는다. 원문 라이선스 및 [OpenStreetMap 저작권 안내](https://www.openstreetmap.org/copyright)를 보존한다. 공개 참조 경계가 현재의 법적 확정 경계라는 주장은 하지 않는다.
4. 각 geometry의 실제 내부 대표점(representative_point), 주 전체 bbox, 대표점 주변0.06도 검색 bbox를 기록했다. 작은 검색 bbox가 선택한 공개 경계 안에 포함되는지 covers 검사를 수행해6개 모두 true를 확인했다. 이 작은 범위에서 256×256 원본 해상도 창을 추출하는 것이며 **주 전체를 영상으로 덮었다는 뜻이 아니다**.
5. `configs/first-group.collection.json`은 canonical ID `south_sulawesi`, `gorontalo`, `southeast_sulawesi`, `banten`, `west_java`, `east_java`를 사용한다. 연차는2020~2025년 동일6~9월로36개 셀이며, 기존 원본 B04/소규모 자료/경계 다운로드 비용을 전체2 GiB 예산에서 미리 차감한다.
6. 첫6개 주의2021년 RGB/SCL/동년 WorldCover 수집을 새 사용자 범위의 정상 승인으로 시작했다. 에이전트의 긴 승인 대기를 root가 해제하고 동일 작업을 이어받았으며, 이 조정 중단은 사용자가 새6개 주 수집을 거절했다는 의미가 아니다. 이전3후보×6년18건 메타데이터 요청의 실제 거절과 분리한다. 실제 완료/실패는 `data/first-group-2021/annual-window-report.json` 및 collection-history.jsonl을 따른다.
7. 수집기능은 config bands를 실제 적용한다. blue/green/red/nir/swir16/swir22를 요청하면 PC B02/B03/B04/B08/B11/B12를 받아 첫 밴드 격자를 기준으로 정합한다. 20 m SWIR 같은 연속형 값은 bilinear로10 m 기준에 맞추고 float32로 보존한다. SCL/클래스 라벨은 nearest를 유지한다. 보간이 실제20 m 정보를10 m 관측으로 새로 만드는 것은 아니다. 원해상도/보간방법/source properties/raster:bands/eo:bands를 기록하며 반사도 scale/offset을 임의 확정하지 않는다.
8. WorldCover 라벨은 source URL과 실제 요청연도에 따라 label_year 및 WorldCover2020v100/WorldCover2021v200을 명시한다.2021 라벨을2020 또는2022~2025년의 동년 정답으로 조용히 재사용하지 않는다.2022~2025 Dynamic World 확률 자료는 실제 인증/export가 완료되기 전 계획 상태다.
9. 36개 셀에 창 하나씩만 받으면 명목상256×256 패치는 최대36개다. 8×8 격자를 주-연도별로 확장하면2304개 후보가 되지만 현재 grid는 **계획만 생성하고 실행 기능은 미구현**이다. 유효1000개 확보, 충분한 클래스 분포, 독립 검증을 달성했다고 표시하지 않는다. 연차 제한 창을 실제 수집하는 기능과 아직 미구현인 대량 공간격자 수집을 구별한다.


6밴드20 m→10 m 정합과 동년 라벨 메타데이터를 검증하는 mock 네트워크 통합 테스트를 추가해 수집·진단24개가 통과했다. 이 테스트가 실제36개 셀 수집 완료를 의미하지 않는다.

첫2021년6주 실행 결과는5개 RGB/동년WorldCover 창 성공, Gorontalo1개 실패였다. Gorontalo 실패는 HTTP Range 기대 범위와 응답 Content-Range의 불일치 검증에서 발생했으며 좌표계 문제라고 단정하지 않는다. 응답 검증을 완화하지 않고 no-cache 요청 헤더와 expected/actual 범위를 포함한 비밀정보 제거 오류 메시지를 추가했다. 원격자산 오류는 기본1회 재시도하며 실패한32 MiB예약분도 전체예산에서 보수적으로 차감한다.

첫5개 창의 유효 픽셀 비율은 South Sulawesi62.9883%, Southeast Sulawesi88.5071%, Banten66.1591%, West Java62.8174%, East Java99.4934%였다. 장면 전체 cloud cover가20%이하라도 작은 표본 창의 구름/NoData 비율은 더 나쁠 수 있다. 실제품질 판정에 이 비율과 클래스별 픽셀 수를 사용하며 파일 수집 성공을 품질 합격으로 대체하지 않는다. 재시도 및 연차 수집의 최신 결과는 실행 manifest를 따른다. 토큰 제거/엄격예산/root 병렬예산 검증을 추가한 data 테스트28개가 정상 호스트에서 통과했다.

## 9. 원본 픽셀 보존과 품질 합격 구분

새 수집 출력부터 다음 자료를 실제 받은 배열 그대로 저장한다. 이 보존에는 추가 네트워크 요청을 사용하지 않으며, 변환 전 배열을 정합 결과로 덮어쓰지 않는다.

- `stac-item.json`: 실제 요청의 STAC feature 및 properties/원본 자산 메타데이터. 필요한 서명 query는 제거하고 파일SHA256을 기록한다.
- `raw-B02.tif` 등 각 입력 밴드: 잘라낸 원래 CRS/해상도/transform과 픽셀 값. B11/B12의20 m native crop을 보존하여10 m bilinear 결과와 독립 비교할 수 있게 한다.
- `raw-SCL.tif`: nearest 정합 이전 범주형 품질자료 원본 창.
- `raw-worldcover.tif`: nearest 정합/클라우드 제외 이전 해당연도 WorldCover 원본 창.
- `quality-mask.tif`: 최종 영상 기준 valid=1/invalid=0 마스크. source_crops 항목은 각 원본 창의 SHA256/CRS/resolution/bounds/transform/보간미적용 상태를 기록한다.

기존 역사적 RGB/라벨 수집 프로세스에는 변환 전 원본 창이 없었다. 따라서 그 파일들에 대해 사후적으로 독립 재투영 픽셀 일치 검증까지 완료했다고 주장하지 않는다. 기존 결과는 보존하고 새 연차 출력에서 원본 창과 정합 결과를 함께 저장한다.

`min_valid_fraction` 기본0.8을 기준으로 `quality_eligible`, `quality_insufficient`, SCL이 없을 때 `quality_unverified`를 별도로 기록한다. 다운로드 성공 상태와 품질 합격을 구분하며 합격해도 정식학습 준비를자동선언하지 않는다. 이전에는 미구현이었던 `candidate_limit=5` SCL사전검토를 보충실험에서 구현·실행했다. 장면구름량오름차순으로 검토해 예비유효85%이상 후보만 선택하며 최종10m/전밴드QA80%를 다시 측정한다. 예비SCL값과 최종값을 구분한다.

## 10. 연차 실제 실패, 공급자 제한 및 전송량 회계 수정

`data/first-group-annual/run-result.json` 및3개 chunk 보고서의36행을 로컬에서 재집계했다. 완성6밴드0개, HTTP429 27행, 전체HTTP본문 예산소진8행, 검색장면없음1행이었다. 실행 전 기존자료 차감은288,334,563 B, 실행 후 reserved_or_transferred_bytes_including_prior는2,147,483,646 B였다. 이 값에는 자산마다 미리 예약했던32 MiB가 실패 시 남은 부분이 포함된다. **실제수신2 GiB 또는 충분한36셀 자료 확보라고 보고하지 않는다.** 기존 예약은 정확한 수신 증거가 없으므로 이번 수정에서 임의 환불하지 않았다.

이 실패 이후 외부 수집을 추가 실행하지 않고 다음 로컬 수정을 mock으로 검증했다.

1. HTTP429는 Retry-After, 요청host, query를 제거한 요청path를 기록한다. 최초429 즉시 worker batch의 circuit을 열고 자산재시도를 중지한다. 후속연도/지역은 deferred_rate_limit로 기록하며 요청하지 않는다. root 총괄기는 state.last_rate_limit를 통해 다른worker에도 중단을 전파한다.
2. read_cog_window는 실패해도 측정된 COG Range본문 바이트와 측정가능 여부를 AssetTransferError로 전달한다. 정상적으로 잡힌 실패의 측정값이 있으면 그 범위만 차감하고 남은 현재예약을 반환한다. 강제중단/정확한 측정불가 실패는 예약을 보존한다. 구버전의 기존예약은 별도로 보존한다.
3. 측정범위는 **Python이 실제 읽어 반환받은 COG Range응답본문**이다. SAS JSON, HEAD, 읽지 않은 오류본문, TLS/header overhead는 제외한다. SAS/HEAD단계 실패의 COG본문0 B를 전체네트워크전송0 B로 표현하지 않는다. partial read 길이가 확정되면 포함하고 내부버퍼의 미확정 바이트는 추정 환불하지 않는다.
4. 서명은 [공식 PC SAS API](https://planetarycomputer.microsoft.com/docs/concepts/sas/)의 account/container token을 만료2분 전까지 process 메모리에 재사용한다. asset마다 sign 호출을 반복하지 않는다. 토큰은 파일/manifest/로그에 저장하지 않는다. 이는 공식 TTL 캐싱 설계이며 공급자 rate limit을 우회하거나429 뒤에 다른 호스트로 재요청하는 기능이 아니다. 신규캐싱의 실제원격재검증은 아직 하지 않았다.
5. 응답 cloud cover를 client에서도 JSON 숫자/유한값/0~100/요청상한 이내로 재검증한다. 관찰된 South Sulawesi2022의20.909931%, Gorontalo2025의20.911454%는 요청20%상한을 넘었다. 공급자 원인을 단정하지 않고 부적합 feature를 제외하며 filtered_count/filtered_items에 근거를 남긴다. 조건위반 자료는 학습입력으로 수용하지 않는다.

실패회계/429즉시중단/기존예약보존/원래HTTP원인 보존/토큰TTL캐싱/응답cloud guard와 병렬 예산 검증을 포함한 data 테스트35개가 통과했다. 이번 테스트는 전부 외부 네트워크 mock이다. 로컬 수정 성공을 실제자료 확보나 공급자429해제로 바꾸어 보고하지 않는다.

## 11. 추가32MiB 보충실험의 실제 결과

신규예산은COG31MiB+JSON/XML1MiB이며 기존원장과의 종합한도는2,181,038,078 B였다. 실제신규차감/측정은14,352,813 B, 종합차감상한은2,161,836,459 B이고 old_ledger_unchanged=true다. 종합값은 기존미측정예약을 포함하므로 실제수신2.16GB라는 의미가 아니다. `data/first-group-recovery32/run-result.json`에 각각기록했다.

| 대상/분할 | 실제촬영일 | 장면cloud | 최종유효픽셀 | 밴드/라벨 |
|---|---|---:|---:|---|
| Banten/validation | 2021-08-17 | 5.46396% | 99.6033% | B02/B03/B04/B08/B11/B12 + WorldCover2021v200 |
| WestJava/test | 2021-08-27 | 7.89399% | 99.9634% | 동일6밴드 + WorldCover2021v200 |

Banten첫후보는 실제COG가중심점을포함하지않아 거부했고65,536 B를 실측차감했다. WestJava앞선두후보의예비SCL유효비율62.8174%/66.2781%를거부하고 세번째후보를선택했다. 실패/부적합후보까지 원본SCL및QA이력을 보존했으며 임의로유효비율을높이지않았다.

두제품XML에서 processing baseline03.00과 BOA_QUANTIFICATION_VALUE=10000을확인하고 XML PRODUCT_URI와STAC product_uri의일치를검증했다. PB04이전의 무offset 공식규칙에 따라6밴드모두scale0.0001/offset0의 보정근거를 보존했다. 이는촬영연도추정이아니라 실제제품baseline/XML/공식해석에근거한다. 각calibration.json은 verified_product_metadata 상태이며 원문XML과해시/밴드순서/제품ID를연결한다.

저장영상은 원본DN을정합한값이며 반사도변환을적용하지않았다. 따라서 reflectance_conversion_verified=false/scale_offset_applied=false와 보정메타데이터verified=true는서로모순이아니다. row.normalization은검증된변환근거이며 실제학습로더가적용할때에만모델입력변환으로취급한다. 새자료는validation/test각1패치여서6밴드train부족, 다른연차미확보, 대표클래스/독립정답/1000패치미달이남아있다. 추가네트워크와재학습은중단하고후속감사를진행한다.

이개선의 metadata누적상한/품질후보선정/PB04offset검증/DNS0바이트1회인계를포함한 data39개테스트가통과했다. 실제두쌍성공의근거는mock이아닌 위원본파일/manifest이며, mock통과를실제정확도로해석하지않는다.
