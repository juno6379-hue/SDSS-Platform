# 추가32MiB 검증·시험지역 수집 계획

사용자의 남은작업 진행 및 충분한 자료 확보 지시에 따라 기존 실패 원장과 별도의 소규모 실험 예산을 설정한다. 기존2GiB는 예제개발 예산이었으며 사용자 명시 절대한도로 해석하지 않는다. 기존 원장2,147,483,646 B는 삭제·환불·초기화하지 않는다.

신규한도32 MiB=33,554,432 B 중 COG 실제읽기/미측정예약31 MiB, JSON/XML메타데이터1 MiB를 적용한다. 기존차감상한과 신규한도의 합은2,181,038,078 B다. 이 값들은 실제수신량과 구분한다. 실행 전 실제디스크 data233,334,616 B, 여유1,999,619,567,616 B를 확인했으며 recovery-plan.json에서 실행시점 수치를 다시 보존한다.

우선대상은 validation용 Banten2021, test용 WestJava2021이다.6개 밴드 B02/B03/B04/B08/B11/B12를 유지하고 동일연도WorldCover와SCL,원본crop/해시를 보존한다. 최대5개 검색후보를 장면구름량 오름차순으로 검토하여 실제SCL 중심창의 예비유효비율85%이상을 선정한다. 최종10m 정합/전밴드NoData/SCL QA80%를 별도검증하며 예비값을 최종값으로 대체하지 않는다.

실행은 단일process, 모든HTTP요청 최소2초간격, 최초작은STAC루트 확인1회 뒤 순차진행한다. 처음HTTP429에서 전부 중단하고 Retry-After/host/path를 보존한다. 과거Retry-After는 기록이 없어 미상이며 임의로해제됐다고 주장하지 않는다. 공식container token TTL캐시만 사용하며 계정·호스트·프록시 변경이나 요청제한 우회는 하지 않는다.

`data/first-group-recovery32/network-attempt.json`을 첫접속전에 기록한다. 동일 보충예산에서 자동반복/원장초기화는 허용하지 않는다. `run-result.json`은 기존원장/새한도/실측/예약/합산상한을 분리한다. 기존data는 덮어쓰지 않으며 이 실행은 모델훈련을 요청하지 않는다.36셀 전체/1000패치/정상데이터셋 확보는 이32MiB실험의 완료기준이 아니다.

공식제품XML이STAC에제공되면 원문을 제한내에 보존하고 quantification/밴드별offset/실제processing baseline을 검증한다. [Copernicus 공식 제품 설명](https://sentiwiki.copernicus.eu/web/s2-products)의 PB04.00이후 BOA_ADD_OFFSET 규칙과 대조한다. 촬영연도로offset을 추정하지 않는다. 검증된 변환메타데이터와 실제이미지에 적용했는지는 별도표시한다.

```powershell
# 네트워크 없는 예산/대상/실행계획 생성
python scripts/collect_recovery_validation.py
# 계획확정 후 한 번의 제한 실행
python scripts/collect_recovery_validation.py --execute
```

## 최초0바이트 DNS실패와 동일보충예산 인계

로컬계획/39개data mock테스트/--help확인뒤 하위에이전트환경에서 최초상태확인1회를 시도했으나 DNS11001이 발생했다. HTTP응답은 없었고 COG0 B, 메타데이터실측/차감0 B, 기존원장불변이었다. `run-result.json`에 이를 보존했으며 이 환경에서 반복하지 않았다.

동일예산의 정상root환경 인계는 `--handoff-after-dns`에서만 허용한다. 검사조건은 DNS분류·HTTPstatus없음·COG0·메타데이터0·기존원장불변·완성manifest없음이다. 원래결과는 dns-attempt-result.json에 보존하고 해시/인계시각을 dns-handoff-started.json에 기록한다. 인계도1회이며429 또는 이미본문이수신된 실패에는허용하지 않는다. 새로운한도를추가하거나기존예산을환불하는기능이아니다.

root가 동일명령을1회실행하여 첫STAC루트확인JSON2,135 B의 실제수신에 성공했다. 이는 하위환경DNS실패와정상root접속을 구분하는 증거이며 아직새픽셀/라벨/정상데이터셋 확보를뜻하지않는다. 이후순차수집의 최신결과는 data/first-group-recovery32/run-result.json을따른다.

```powershell
python scripts/collect_recovery_validation.py --execute --handoff-after-dns
```
