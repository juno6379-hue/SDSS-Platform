# 03. 개발 순서와 병렬 작업 로드맵

## 1. 순서 원칙

요구사항/데이터 평가 → 공통 계약 → 수집 → AI-ready package → CPU baseline → 독립평가 → 승인/배포 → T1/T2 변화 → SDSS → 근거 질의 → 실증/UAT 순서다. 독립 모듈 코드는 병렬로 작성하되 앞 단계의 실자료 인수조건을 통과하기 전 다음 단계 성능·실증을 완료로 보고하지 않는다.

## 2. 에이전트 분담

| 담당 | 소유 범위 | 병렬 결과 | 통합 순서 |
|---|---|---|---|
| 총괄 | API/store/lifecycle/기본문서/환경 | FastAPI·작업큐·승인·요구추적·통합시험 | 계약 합의 후 어댑터 연결 |
| 데이터 에이전트 | app/data, 수집시험·진단/일괄수집 script, docs06/10 | STAC/DW/WC·제한다운로드·진단 | 원본→manifest→라벨정합 |
| ML 에이전트 | app/ml, ML시험, docs07 | 실제 CPU 학습·추론·지표·변화 | dataset→checkpoint→GeoTIFF/CSV |
| SDSS 에이전트 | frontend, docs08 | React/MapLibre·API·폴링·registry UI | 실제 API 결과 표시 |

코드 주석과 개발기록은 한국어로 작성한다. 모듈 간 입력·출력 계약은 메시지와 코드로 동기화하고 중복 파일 편집을 피한다.

## 4. TECH-5 대응

TECH-5 PDF2~3쪽 D1~D4는 설계/DB명세/PoC/모델·Toolbox·SDSS prototype로 연결한다. 이번 산출물은 이 초기 개발의 일부다. PDF3~5쪽 D5~D16은 3개 지역군의 주제모델 검증·통합위험·RDTR·성능보고·가이드·통합플랫폼이다. PDF5~6쪽 D17~D21은 pilot/UAT, 플랫폼 성능, 사용·운영 가이드, RDTR 전체 구현, 정책 연계 이관 로드맵이다.

원문은 27개월 일정이다. PDF2쪽의 색상 일정은 렌더 확인했으며, 실제 착수일이 제공되지 않아 달력상 납기나 원문 월별 막대 구간을 임의의 날짜로 바꾸지 않았다. 이번 세션을 D1~D21 완료로 해석하지 않는다.

## 5. 다음 개발 우선순위

1. 로컬 진단스크립트로 DNS/HTTPS/STAC 상태 확인 후 허용된 네트워크에서 수집.
2. 공식 AOI 확정, 시기·센서·구름 조건을 맞춘 충분한 실자료와 전문가 참조 확보.
3. 실자료 baseline과 independent hold-out 평가, 입력정규화/분류체계 확정.
4. MLflow/PostGIS·분산큐·권한분리와 운영회복 시험.
5. COG 지도결과, RDTR overlay, 근거문서 RAG와 현장 UAT 순서로 확대.
