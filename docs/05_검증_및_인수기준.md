# 05. 검증 및 인수기준

## 1. 검증 수준

코드 존재와 import 성공만으로 구현 인수를 판정하지 않는다. 모의 네트워크 시험은 요청/응답 처리 검증, 합성 GeoTIFF 시험은 연산 기능 검증, 실제 픽셀 창은 접속/읽기 검증이다. 실제 자료 학습과 독립 전문가 참조평가는 별도 증거가 필요하다.

## 2. 자동시험

저장소 루트 PowerShell에서 `scripts/test.ps1` 또는 `python -m unittest discover -s tests -v`를 실행한다. 개발용 `.runtime` 설치를 사용할 경우 `PYTHONPATH=.runtime;backend`를 지정한다. 테스트 목록과 실제 통합 결과는 docs09에 기록한다.

| 시험 | 검증 내용 | 성공 기준 |
|---|---|---|
| 데이터 입력 | bbox/date/cloud/limit/허용 URL/경로 | 범위 밖 입력·루트 탈출 거부 |
| 다운로드 | byte cap/hash/중복/Range/중단 | 초과/오류 실패, 원본 덮어쓰기 없음 |
| 모의 STAC | 실제 응답 형태의 feature/assets | ID/date/cloud/assets 추출 일치 |
| 진단 | DNS/HTTP/TLS/payload 오류 구분 | 실패 단계 이후를 성공처리하지 않음 |
| ML split | 지역/group/해시/겹침 | 교차분할 누출 거부, seed 재현 |
| 라벨 | confidence/클래스/최근린 | 저신뢰/NoData 제외, 범주값 보존 |
| CPU 모델 | 실제 2epoch 합성 학습→checkpoint→추론 | 유한 loss, 래스터 CRS/shape 보존 |
| 지표 | known confusion | OA·IoU 정확한 수치 일치 |
| 변화 | 정합/NoData/단위/전이 | 10m 픽셀 1개 전환=100m², nodata 제외 |
| 승인 API | Draft/독립근거/배포 | 미승인 운영추론·배포 거부 |
| API 이력 | 실패작업/재시작/근거질의/보고서 | 오류보존, 빈상태에 임의자료 없음 |
| frontend | TypeScript·Vite build | 컴파일·번들 성공; 브라우저 UAT와 구분 |

## 3. 실데이터 통합 인수 시나리오

1. 서버 실행, 3개 확정 AOI 입력 및 권한 확인.
2. S2 T1/T2 실제 검색 ID/date/cloud/밴드 목록과 응답 저장.
3. 예산 내 다중밴드 수집·체크섬·원본보존·출처/조건 확인.
4. DW/WC·전문가 참조 획득, 시기/분류체계 차이와 정합 QA.
5. 유효 패치 1,000~3,000 목표 및 지역/클래스/시기 대표성 확인.
6. group hold-out으로 baseline 학습·버전/checkpoint/입력정규화 기록.
7. 독립 참조로 OA/F1/IoU·오류지도·지역/시기 차이 평가, 적합성 전문가 판정.
8. Draft→Validated→Approved→Deployed 승인·역할·근거 보존.
9. T1/T2 변화, 투영/측지 면적, 행정구역/계절/오차 검토.
10. WebGIS 실제 결과 비교·레이어·통계·전이행렬·다운로드 확인.
11. 자연어 질의에 데이터/모델/기간/품질 근거 일치, 불충분 근거 명시.
12. 보고서/실행이력·재현·배포복구·성능/보안/현장 UAT 확인.

사업 성능 목표와 표본설계는 발주처와 확정해야 한다. 임의 90% 등 정확도 목표를 달성한 것으로 표시하지 않는다. 현재 위 전체 시나리오의 운영 인수는 완료되지 않았다.

## 4. 실패와 재시험

DNS 실패는 서버/검색 API 오류라고 단정하지 않는다. DNS 성공 후 HTTPS 실패는 TLS/방화벽/프록시/timeout을 구분하고 HTTP4xx/5xx는 응답코드와 본문계약을 확인한다. 로컬 프록시/허용도메인은 docs10에 기록한다. 권한이 차단되면 정식 승인 밖 경로로 우회하지 않는다.

Windows 샌드박스가 asyncio 내부 socketpair를 차단하면 API TestClient도 시작 전 멈출 수 있다. traceback의 이벤트루프 생성 단계와 application handler 진입을 구분하고 허용된 로컬 환경에서 재시험한다. 이것만으로 API 구현 결함이라고 판단하지 않는다.
