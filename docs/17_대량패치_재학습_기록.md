# 대량 패치 준비와 LCLUC 재학습 실행 기록

기준일: 2026-10-16. 이 기록의 새 대량 자료 모델은 아직 학습하지 않았다. 기존 3개 실제 패치·3 epoch 실험의 가중치는 보존한다. 실제 수집, 충분성 통과, 학습 완료, 독립 정확도 검증은 각각 별도의 증거가 필요하다.

## 1. 목표와 개발 순서

1. 실제 원본에서 생성한 256×256 비중복 적격 패치 1,000~3,000개를 확보한다. 합성 텐서·복제 파일·명목 격자를 실제 패치로 세지 않는다.
2. 실제 영상·라벨·품질 마스크·제품 보정 메타데이터를 해시로 연결하고 연도와 분류 의미를 검사한다.
3. 지역·원본 scene·같은 공간의 모든 연차를 동일 분할로 묶는다. 실제 패치 수·대표성·클래스 분포 검사 후에만 dataset을 만든다.
4. train 통계로만 클래스 가중치를 계산하고 CPU Tiny U-Net을 최대 20 epoch 학습한다. validation loss로 선택한 best checkpoint를 별도 test 분할에서 평가한다.
5. OA, mIoU, 클래스별 precision/recall/F1/IoU, 실제 참조 픽셀 수와 예측 클래스 비율을 보고한다. 출력 붕괴 여부를 별도로 검사한다.
6. 완료된 모델도 Draft로 등록한다. 독립 전문가 holdout 없는 의사라벨 일치도로 운영 승인을 부여하지 않는다.

## 2. 6개 주와 공간·연차 분할

| 분할 | 주 | 최소 조건 |
|---|---|---|
| train | South Sulawesi, Gorontalo, Southeast Sulawesi, East Java | 합계 600개 이상, 주마다 50개 이상·서로 다른 공간 32곳 이상 |
| validation | Banten | 100개 이상 |
| test | West Java | 100개 이상 |

전체 합계 하한은 1,000개이다. 600+100+100만으로는 통과하지 않는다. 각 분할에 물·나무·rangeland·작물·시가지·나지 클래스가 각각 최소 256 유효 픽셀 있어야 한다. 이는 최소 검사이며 주 전체의 통계적 대표성이나 목표 정확도를 보장하지 않는다.

전체 목표는 6개 주 × 2020~2025년의 36개 조합이다. 같은 위치의 다른 연도 관측은 별도 실제 관측 패치로 집계하지만 공간 대표성은 한 위치로 센다. 같은 위치·같은 연도의 반복 관측은 다른 파일 해시라도 중복으로 차단한다. 원본 scene이나 공간 범위가 분할을 가로지르면 차단한다. Central Java는 이번 First Group에 속하지 않는다.

수집 담당의 `collect_training_grid.py`는 원격 1024 창을 보존하고 실제 256 패치 16개로 분할한다. 지역 내부 비율 0.95 이상과 외부 품질/라벨 유효 비율 0.8 이상인 패치만 제출한다. `source_window`, 원본 해시, scene, province, year와 연도 없는 `spatial_location_id`를 보존한다. 수집기 후보 수를 학습 적격 수로 간주하지 않고 ML gate가 실제 파일을 다시 계산한다.

## 3. 입력·보정·분류체계 계약

입력 순서는 B02/B03/B04/B08/B11/B12이며 원본 DN에 제품별 `DN * scale + offset`을 적용한다. B11/B12의 20m 원본과 10m 정합 과정은 수집 근거에 보존한다. 제품 보정은 `calibration.json`의 검증 상태, 원본 XML SHA, 제품 ID, 밴드 순서, 채널별 scale/offset과 출처 URL이 일치해야 한다. 다른 처리 기준의 offset을 추정하여 재사용하지 않는다.

새 6년 실험은 동일 Esri/Impact Observatory v003 연간 의사라벨을 사용한다. 연간 파일의 시작·종료 연도와 영상 연도가 같아야 한다. WC2021을 다른 해 정답으로 복제하거나 WC와 Esri를 한 실험에 혼합하지 않는다.

| Esri 원래 값 | 내부 코드 | 의미 |
|---|---|---|
| 1 | 0 | water |
| 2 | 1 | trees |
| 11 | 2 | grass_or_shrub_rangeland |
| 4 | 3 | flooded_vegetation |
| 5 | 4 | crops |
| 없음 | 5 | unused_separate_shrub_class; logit 제외 |
| 7 | 6 | built |
| 8 | 7 | bare |
| 9 | 8 | snow_and_ice |
| 0, 10 | 255 | NoData, clouds; loss/통계 제외 |

코드 2의 의미는 과거 WC grass와 다르다. dataset/checkpoint/report/각 분할 metrics/inference/timeseries에 `class_names`와 `label_taxonomy_signature`를 전달한다. 새 모델의 독립 평가 요청도 같은 분류체계 서명을 제출해야 한다. 과거 WC 실험의 클래스 이름과 가중치는 변경하지 않았다.

새 실제 제품별 정규화 모델의 추론에는 `normalization`과 `source_scene={scene_id,image_sha256,band_names}`가 필요하다. 실제 입력 영상 SHA, 제품·밴드 서명, 보정 근거 SHA와 원본 XML SHA 및 적용 scale/offset을 다시 검사한다. 이는 제출된 출처 기록의 일관성 확인이며 제출자 진술의 공인 인증은 아니다. 합성 fixture는 별도로 표시한다.

## 4. 실행 가능한 계획과 현재 증거

정식 계획: `data/first-group/experiment-esri-v003-2020-2025.json`. 별도 `experiment-esri-v003-2020-2021.json`은 `limited_period_experiment=true`와 범위를 명시한 개발 계획이다. 축소 계획의 통과/학습을 사용자 전체 2020~2025 목표 달성으로 보고하지 않는다. 두 계획 모두 실제 1,000개 하한과 고정 4/1/1 분할을 유지한다.

```powershell
python scripts/run_experiment.py --manifest data/first-group-training-esri-v1/annual-window-report.json --plan data/first-group/experiment-esri-v003-2020-2025.json
```

이 단계는 파일 QA와 `data/first-group/training-readiness.json` 작성만 수행한다. `--execute`가 없으므로 학습하지 않는다. 실제 ready 통과 후에만 고유 run-id를 부여해 다음 단계로 진행한다.

```powershell
python scripts/run_experiment.py --manifest data/first-group-training-esri-v1/annual-window-report.json --plan data/first-group/experiment-esri-v003-2020-2025.json --execute --run-id esri_v003_full_v1 --epochs 20 --max-seconds 1800 --epochs-per-call 20
```

문서 작성 시점 새 ESRI 보고서는 `collecting`, scenes 0이며 현재 실행 결과는 적격 0개, 0/36 조합, blocker 27개로 blocked이다. 수집 도중 보고서는 바뀌므로 이후 해시가 달라지면 기존 readiness는 stale이며 반드시 재평가한다. 현재 ready 상태나 새 성능 수치는 없다.

기존 recovery32의 WC 6밴드 실제 2개 패치는 validation 1/test 1/train 0이다. 최신 충분성 정책으로 별도 확인하면 blocker 19개이다. 기존 RGB와 섞은 품질 재고 5개를 새 ESRI 적격 패치로 집계하지 않는다. 기존 `quality-audit-current.json`은 공간·연도 6셀/실제 창 8개라는 재고 기록이다.

## 5. CPU 시간 제한과 정확한 재개

`benchmark_ml_cpu.py`의 `data/audits/cpu-training-benchmark.json`은 합성 텐서 계산 시간 측정이다. 저장 모델·실제 학습 자료·정확도 증거가 아니다. CPU torch 2.14.0+cpu, batch 1, thread 2, 입력 6×256×256에서 학습 step 중앙값 0.1521초, forward 0.0340초를 측정했다. 700 train/150 val 기준 1 epoch 순수 계산 약 111.6초, 20 epoch 약 37.2분이다. 실제 NPZ 읽기·해시·전처리와 저장 비용을 제외한 추정이므로 첫 실제 epoch 후 시간을 다시 판단한다.

실학습은 최대 20 epoch, 호출별 기본 1,800초다. `best.pt`는 validation loss 최저 가중치, `last.pt`는 마지막 완료 train+validation epoch의 모델·optimizer·scaler·seed/RNG·history·early stopping 상태다. 파일은 flush/fsync/close 후 원자 replace한다. 예산 초과 시 미완료 epoch는 다음 호출에서 처음부터 다시 수행한다. `paused_training`은 완료된 학습이 아니며 test metrics는 null이다.

```powershell
python scripts/run_experiment.py --manifest data/first-group-training-esri-v1/annual-window-report.json --plan data/first-group/experiment-esri-v003-2020-2025.json --execute --run-id esri_v003_full_v1 --epochs 20 --max-seconds 1800 --resume
```

재개할 때 dataset/출처 해시·계획·학습 설정을 바꿀 수 없다. 완료 실험과 과거 baseline을 덮어쓰지 않는다. 중단 실험의 `experiment.json`에는 dataset 경로와 상태를 먼저 남겨 프로세스 중단 후 이어갈 수 있게 한다. 완료 후에는 선택 validation 및 실제 test 혼동행렬로 최소 두 클래스 출력과 최대 지배 비율 0.995를 검사한다. 이 다양성 검사도 정확도 기준은 아니다.

## 6. 검증 결과와 남은 단계

- 부모 정상 host에서 pipeline 15개 시험 PASS, 36.984초. epoch 분할 재개와 연속 학습의 history·optimizer/RNG 재현·가중치 동일성, 예산 중단 시 미완성 test metrics 비공개를 확인했다. 서브 에이전트 임시 폴더의 WinError5는 환경 제약으로 별도 기록하며 원자 저장 방식을 우회하지 않았다.
- 추가 Esri 2개 시험 PASS, 10.207초. cloud/NoData 무시, rangeland 의미, reserved5 logit 제외, 잘못된 WC 분류서명 평가 거부와 시계열 class_names 전달을 확인했다.
- readiness 12개 시험 PASS, 8.846초. 실제 하한 강제, 합성 계수 금지, 출처·연도·공간 중복·혼합 분류체계 차단, 클래스 불균형과 실제 입력 영상/제품 보정 근거 변조 거부를 확인했다.
- 추가 runner 재개 계획 변경 거부 시험 1개 PASS, 0.975초. 이전 실험 기록을 수정하거나 train을 호출하기 전에 거부한다.

새 수집 완료 후 같은 gate를 실행하고 적격 개수·split·클래스 및 36셀 coverage를 보고한다. 충분할 때만 재학습하며 완료 report/checkpoint/dataset manifest SHA를 MLOps 등록 담당에게 전달한다. 등록은 Draft, independent_evaluation=false를 유지한다. 현재는 실제 대량 재학습과 새 모델 OA/mIoU가 없으며, 전문가 독립 정답을 이용한 최종 정확도·운영 승인은 미달이다.

## 7. 첫 실제 Esri 16개 패치의 후속 QA

위 0개 상태 이후 실제 Gorontalo 2020년 g00 원본 1024 창에서 16개 256 패치를 확보했다. 수집을 추가 호출하지 않고 별도 snapshot과 `data/audits/esri-gorontalo2020-initial16-quality.json`, `esri-gorontalo2020-initial16-readiness.json`에 감사 결과를 보존했다. 수집 중인 main readiness는 이 임시 감사로 덮어쓰지 않았다.

16개 영상은 모두 6×256×256 float32이며 서로 다른 영상 SHA 16개/공간 위치 16개/공간 중첩 0쌍이다. 동일 원본 scene·source_group 1개에 속하며 train으로 묶였다. 외부 품질 및 참조라벨 유효 비율은 95.4163~100%다. 제품별 normalization의 제품ID·밴드·scale/offset·보정/원본XML SHA를 검증하고 원본 창·raw 6밴드·SCL·Esri 원본·STAC·calibration 11개 출처 파일 SHA를 확인했다. QA의 DN 분위수는 각 밴드 유효 픽셀 매 128번째 샘플로 계산했으며 전체 래스터 극값으로 해석하지 않는다.

| 참조 클래스 | 유효 픽셀 | 비율 | 클래스가 256픽셀 이상 포함된 패치 |
|---|---:|---:|---:|
| water | 116 | 0.0112% | 0 |
| trees | 1,013,377 | 97.7703% | 16 |
| rangeland | 5,955 | 0.5745% | 3 |
| crops | 16,874 | 1.6280% | 2 |
| built | 166 | 0.0160% | 0 |
| flooded / bare / snow | 0 | 0% | 0 |

이 자료는 산림에 크게 편중되어 있다. 단순 256픽셀 최소 coverage와 클래스 가중치만으로 균형 자료가 확보됐다고 주장하지 않는다. 수집 담당에게 도시·수변·나지·농경지의 서로 다른 실제 공간 창을 우선 보충하도록 요청했다. 같은 산림 위치의 연차 패치만 늘리는 방법은 공간·클래스 대표성을 해소하지 않는다.

기본 개발 정책에 분할별 최대 참조 클래스 비율 90%, 주요 여섯 클래스 각각 최소 0.5%, 각 클래스가 최소 256픽셀 포함된 패치 5개 이상을 추가했다. 수치는 명시적으로 조정·기록하는 샘플 선정 휴리스틱이며 자연 모집단 비율이나 독립 정확도 인수 기준이 아니다. 희귀 클래스 후보를 확보하고 클래스 포함 패치의 실제 분포를 보고한 뒤 최대 3,000개 범위에서 대표 부분집합을 명시적으로 선택한다. validation/test 가중치를 train에 사용하지 않는다.

gate는 `reference_balance_by_split`, `class_patch_counts_by_split`과 실패 사유를 반환하며 준비된 실제 NPZ에서도 픽셀 비율과 클래스 포함 패치 수를 재계산한다. 후속 감사 결과 train 16/val 0/test 0, 27개 차단 사유로 blocked이다. 학습하지 않았다. 균형 정책의 지배 클래스·미소 비율·한 패치 집중·한 픽셀만 존재하는 가짜 coverage 차단을 추가한 readiness 전체 15개 시험은 9.723초 PASS다.

## 8. 초기 6개 배치 완료 후 77개 적격 패치 감사

첫 6개 배치 종료 후 main `training-readiness.json`을 실제 전체 보고서로 다시 계산했다. 물리 파일 80개 중 유효 비율 기준을 통과한 실제 256 패치는 77개이며 train 45/validation 16/test 16이다. 확보된 조합은 2020년 다섯 주뿐이므로 5/36개다. 주별 적격 수는 South Sulawesi 0, Gorontalo 16, Southeast Sulawesi 13, East Java 16, Banten 16, West Java 16이다. 모든 학습 주의 최소 패치·공간 대표성 기준과 전체 1,000개 하한을 충족하지 못했다.

| 분할 | water | trees | rangeland | crops | built | bare |
|---|---:|---:|---:|---:|---:|---:|
| train | 0.0722% | 78.6614% | 1.2777% | 12.5031% | 7.4848% | 0.0008% |
| validation | 0.1147% | 85.6783% | 0.7024% | 8.6657% | 4.8389% | 0% |
| test | 0.0632% | 2.5465% | 1.3779% | 2.2356% | 93.6552% | 0.0176% |

모든 분할에 수변·나지 샘플이 부족하고 test West Java는 시가지에 편중되어 있다. train flooded_vegetation은 0픽셀인데 test에 1,087픽셀이 있어 미학습 참조 클래스 차단도 발생했다. 전체 gate는 16개 차단 사유로 blocked다. 77개 확보를 학습 준비 완료나 정확도 성과로 보고하지 않는다.

별도 `data/audits/esri-initial6batch-inputs.json`과 `esri-initial6batch-quality.json`에 물리 패치별 영상/라벨/마스크 SHA·정규화 검증·품질·source_group·실제 공간 위치와 출처 파일 해시 검사를 보존한다. 수집 담당에게 South Sulawesi 유효 후보, 각 분할 수변·나지와 West Java의 도시 외 공간을 우선 보충하도록 전달했다. 코드 변경·추가 HTTP 수집·실제 재학습 없이 로컬 감사만 수행했다.
