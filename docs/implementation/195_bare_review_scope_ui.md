# 195 — 나지 후보 검토의 실제 탐색 범위 표시

상태: TESTED_SYNTHETIC(범위 검증·화면 렌더), VERIFIED_REAL(새 API 적용·기존 179 호환·192/193 게시 후 최종 실제 화면). 원격 품질·집행·학습 승인은 미충족이다.

## 쉬운 설명과 문제

기존 179 검토는 6개 주 전체의 후보 50개를 다뤘지만, 새 192 검토는 고론탈로와 서자바만 탐색한 후보 37개를 다룬다. 나머지 주의 0은 그 주를 탐색해서 후보가 없었다는 뜻이 아니다. 이번 변경은 보고서가 **어느 주를 탐색했는지** 화면에서 직접 보여준다. 새 탐색·수집·품질 검사나 승인 기능은 추가하지 않았다.

## API 계약

명시적으로 게시한 보고서의 `ui_summary.searched_provinces`를 선택 필드로 받는다. 값은 공식 6주 ID의 비어 있지 않은 중복 없는 부분집합이어야 한다. 빈 목록·중복·빈 문자열·임의 주·문자열 대신 목록이 아닌 값·중첩 목록을 거부한다. 해당 필드가 없으면 기존 179 보고서 호환을 위해 공식 6주로 해석한다. 명시적 null은 누락과 다르며 거부한다.

기존 `summary_by_province`의 6행·행 합계·전체 합계·SHA·관측 시각·false 승인 플래그 계약은 유지한다. 탐색 범위 밖 행의 `candidates > 0`도 모순으로 거부한다. 따라서 게시 보고서에는 여전히 6행이 있어야 하고, 범위 밖 행은 0이어야 한다. API `bare_target_review.searched_provinces`에 검증한 목록의 복사본을 반환한다. 오류는 기존 `INVALID_OR_BLOCKED_REPORT`로 닫고 후보 0개로 대체하지 않는다.

원본 192 보고서는 수정하지 않는다. Root가 고정된 190 proposal의 탐색 범위를 확인한 게시용 복사본에만 해당 필드를 추가하고 별도 receipt를 발행한다. 이 구현은 pointer나 보고서 게시 자체를 수행하지 않는다.

## 화면 계약

프론트 adapter도 같은 범위를 독립 검증하며, 누락은 6주로 호환한다. 잘못된 검토가 있어도 현재 재고 집계는 유지하고 검토 부분만 미확인으로 표시한다. 화면은 `이번 탐색 대상: 고론탈로 · 서자바`처럼 한국어로 명시하고, 범위 밖 주는 미탐색이며 후보 0개로 판단하지 않는다고 설명한다. 검토 표에는 탐색한 주만 표시한다. section 접근성 이름도 6주라고 고정하지 않는다.

로컬 후보·과거 지원 범위 검사와 원격 품질·실제 취득·집행·학습 승인은 계속 구분한다. 원격 미검사·집행 미승인, 현재 source와 검토 source 시점 차이, 현재 재고와 고정 학습 후보의 구분을 유지한다.

## 최종 게시 후 실제 화면 확인

Root가 192 게시용 보고서와 193 후보 receipt를 승계한 뒤, 새 API PID 20676을 사용하는 기존 Chrome view17에서 명시적으로 **한 번** 새로 조회했다. HMR 이전 화면 관측과 별개로 실제 새 응답 **13:18:35.852026 KST**를 확인했다. 응답 source SHA는 `ab745b908e2e0adce80907554216c0529e950c7e0123a7f85ee664cf26d50d0f`다.

새 검토는 후보 37개이며 **고론탈로·서자바 두 주만** 표에 표시된다. 고론탈로 8개(과거 비겹침 2 / 겹침 6), 서자바 29개(2 / 27), 로컬 부적합은 각각 0이다. 탐색 범위 밖 주는 미탐색이라는 설명, 검토 source와 현재 source 일치, 원격 품질 미검사·집행 미승인 문구를 실제 확인했다. 기존 50개 보고서의 네 주를 탐색 0개로 덮어쓰는 표시가 아니다.

현재 원본 적격 1333(791·292·250), 셀 부족 33과 **새 고정 QA 후보 1317(791·276·250), 차단 3건**이 분리된다. 후보 생성 source는 현재 원본과 일치한다고 표시하지만 학습 준비·독립 정확도·배포 승인은 아니다. 콘솔 warning/error는 0건, 가로 넘침은 없다. 진행 예정 196의 성과는 포함하지 않는다.
