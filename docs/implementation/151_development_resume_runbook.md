# 151 — 147 마감·중단 수집·학습자료 보완을 잇는 재개 안내

기준: 2026-10-18. 이 문서는 사용자의 “쉽고 상세한 설명” 요청과 실제 재개 절차를 함께 기록한다. 실행 상태는 시간에 따라 바뀌므로 마지막 관측·로그를 함께 읽는다. 전체 프로젝트 완료 선언이 아니다.

## 147 통합 마무리는 무엇인가

147은 이미 끝난 local LCLUC 분석의 성적표를 GeoLLM 화면에서 찾아 읽는 기능이다. 사용자가 저장된 Workflow ID를 입력하면 기록과 보고서를 읽고, 보고서의 SHA-256 지문·모델·관측 연도·변화 집계를 확인한 뒤 요약을 보여준다. 같은 분석의 지도와 전이행렬을 수동으로 열 수 있다.

통합 마무리에는 다음 다섯 가지가 포함된다.

1. 화면과 기존 조회 API 연결: 분석을 새로 실행하는 POST 없이 저장 기록만 GET한다.
2. 서로 맞는 기록 결합: 다른 모델·연도·보고서를 잘못 섞지 않고, 실패·진행 중 상태를 성공 자료로 표시하지 않는다.
3. 실제 화면 점검: 임시 합성 자료의 실제 서버에서 인증·정상/실패·지도·행렬·메뉴 이동을 확인한다.
4. 문서와 이해자료 반영: 개발자용 사용법·시험 근거와 비전공자용 설명·발표·FAQ를 같은 결과로 맞춘다.
5. Git 마감: 변경 파일과 근거를 커밋해 다음 개발자가 같은 상태에서 이어갈 수 있게 한다.

이 다섯 항목은 commit `76949f6`으로 완료됐다. [147 상세 근거](147_geollm_workflow_evidence_ui.md)는 집중9·전체 프론트280·관련 백엔드34·독립7 PASS와 빌드 및 실제 합성 브라우저 시험을 구분한다. 처음 조사할 때는 API 서버가 없고 frontend5174만 실행 중이었다. 후속으로 기존 코드의 토큰 미설정 로컬 개발 모드를 확인해,API도 이 기기 안의127.0.0.1:8002로 복원했다. 토큰이나 인증 코드는 변경하지 않았다.10:01 실제 API·프론트 proxy GET200, 사용자 브라우저의 연결됨 표시,147 빈ID/읽기버튼 비활성, catalog14행 지문 불변을 확인했다. 현재 화면은 [로컬 플랫폼](http://127.0.0.1:5174/)에서 연다. 운영 Workflow를 새로 만들어 보고서를 생성한 것은 아니다. [150 서비스 조사](150_service_recovery_audit.md)에 초기 보류와 후속 복원·브라우저 확인을 구분한다. LLM 답변·정책 RAG·운영 모델 승인은 이 기능에 포함되지 않는다.

## 중단된 수집은 무엇인가

대상은 Sentinel-2의 반텐 2023년·서자바 2023년 영상창 두 건이다. 한 창에는 6개 밴드와 품질·동년 참조라벨이 함께 필요하다. 일부 밴드만 있는 것은 아직 완성 학습자료가 아니다.

반텐에는 B02/B03/B04/B08/B11, 서자바에는 B02/B03/B04의 부분 원본이 남았다. 각 작업의 종료 보고서와 worker-result가 없어 전송 정산 완료를 확인할 수 없다. 마지막 실제 부분 작업 기록은 10월16일 약17:04이며 합산 manifest/장부 마지막 수정17:00:45와 구분한다.

Windows 로그에는 비정상 종료와 10월17일 재부팅이 확인된다. 다만 이벤트의 이전 종료 시각16:53:55와 파일 시각17:04가 충돌하므로 collector의 정확한 종료 순간·직접 원인을 확정하지 않는다. 현재 원장에는 예산 부족·429로 정상 종료됐다는 근거도 없다.

재개를 막던 장치는 두 가지다. 실행 프로세스가 없는데도 남은 잠금 파일, 그리고 미정산 pending key를 자동 재실행하지 않는 예산 보호다. 잠금은 “작업자가 이 장부를 사용 중”이라는 표지다. 이 파일은 PID 없는 빈 파일이라 파일만 보고 주인을 확인할 수 없다. pending 예약은 “이전 작업이 얼마를 받았는지 최종 확인되지 않았으므로 최대치를 일단 잡아 둔 금액”에 해당한다.

## 이번에는 어떻게 실제로 다시 시작했나

기존 두 건의 136,314,880B 예약과 부분 파일을 보존했다. 원장·합산 보고서·run-result·계획의 원바이트 사본을 `data/collection-continuation-backup-20261018/`에 저장해 지문을 확인했고, 원본 빈 잠금도 그곳에 이동해 보존했다. 실제 collector/monitor가 없는지 확인한 뒤 기존 O_EXCL 방식으로 하나의 실행자만 새 잠금을 얻었다.

새 `--continue-unrelated-pending` 옵션은 기존 pending의 설정 지문이 같은지 확인해 그 두 key만 실행 후보에서 뺀다. 기존 작업을 정상 정산하거나 예약을 환불하지 않는다. 기본 옵션 없이 실행할 때의 보수적 차단은 유지한다.

09:52:13 KST, PID532로 남술라웨시2021/2022 공간창03의 신규 두 작업을 시작했다. 두 worker_started와 신규 예약 정확2건을 독립 확인했다. 같은 4GiB 신규 총예산·최대3000패치·2worker·전체 요청 최소2초 간격·첫429 공유 중단을 유지했다. 이번 실행은 `--max-batches 2`로 제한했고09:57 관측에서 두 작업 종료·잠금 정상 해제·429없음을 확인했다.

2021년은 확대 참조가 나무 약98.49%·나지4픽셀이어서 다양성 정책이6밴드 수신 전에 보류했다.2022년은16패치를 생성했고11개가 품질 적격이었다. 누계는1,400물리/1,122적격/278부적격, 적격train/validation/test는639/233/250이다. 신규 두 작업 계상은19,548,647B이며 신규 예산 잔여는2,341,906,244B다. 기존 중단 예약136,314,880B·부분파일·기존정산기록·catalog·후보·과거원장은 독립 최종 대조에서도 보존됐다. 신규16패치의 나지는0픽셀이므로 나지 부족 해결 성과로 세지 않는다.

실행 예시는 [148](148_collection_resume_audit.md)에 있다. Root만 `collection-resume-handover-20261018.ps1`을 한 번 수행했으며 같은 스크립트를 다시 실행하지 않는다. 기존 백업과 실행 기록이 있으면 거부하도록 되어 있다. 현재 실행 여부를 먼저 확인하고 별도 다음 주기를 결정한다.

## 학습자료 보완은 무엇을 고치는가

재개 전 원본 품질 적격1,111개는 실행 전 사본으로 보존되어 있다. 같은 위성 scene이 validation/test에 걸친 문제를 제외한 별도 후보는1,095개(628/217/250)다. 후보 발행·staging·QA가 이미 있었으므로 “아직 후보도 없다”라고 설명하면 안 된다. 이번 수집 후 원본 누계는1,122개지만, 새 자료가 자동으로 이1,095개 후보에 합쳐지는 것은 아니다.

ML 담당의 첫 재검사는 병렬 수집이 부모 합산 보고서·원장을 갱신하면서 최종 지문 대조에서 미확정으로 종료했다. 이를 성공으로 처리하지 않았고 최초 실패 근거도 보존했다. 재검사는 실제 입력인 고정 후보·정책·기존 파일과 실행 전 보존 사본을 기준으로 분리했다.296.625초·종료0으로 기존1,095개 후보의4차단/학습준비false와13개 비교 필드가 그대로임을 확인했다. 추가로4,285개 파일을28.188초 동안 실제 재해시해 불일치0을 확인했다. 이는 새 수집분을 포함한 최신 후보 전체 QA와 별개다.

현재 핵심은 맨땅·나지인 bare 클래스다. 예를 들어 숲 사진이 대부분이고 맨땅을 거의 못 본 학생은 맨땅 문제를 제대로 풀기 어렵다. 따라서 다음 조건을 각각 본다.

- 절대 픽셀 수: split별 bare 최소256픽셀. 기존 후보 validation은209여서 이 바닥만 보면47 부족하다.
- 표본의 분산: 한 패치에 bare가256픽셀 이상 있어야 기여 패치로 센다. 그런 패치가 train/validation/test 각각 최소5개 필요하다. 현재 후보는 모두0개다.
- 비율: split의 유효 참조 픽셀 중 bare가 최소0.5%여야 한다. 현재 세 split 모두 기준 미달이다.

47픽셀만 더한다고 전체 조건을 통과하는 것이 아니다. 전체 패치 수와 공간 고유위치 조건은 현재 후보에서 이미 충족하며, 지역×연도 셀당28개 계획의 부족151개도 위 클래스 차단과 별도 지표다. 참조 ESRI 라벨은 해당 연도 자료를 사용하지만 독립 현장 정답은 아니다. 독립 검증용 라벨은 아직 확보되지 않았다.

이번 로컬 조사에서는 이미 저장한 반텐 참조라벨17개로부터 bare가 있는 작은256창10개를 찾았다. 여러 연도·겹침을 포함하므로 독립10곳이 아니다. 기존1024창으로 확대하면 기존 영상과 겹쳐 기존 후보 수집기에 바로 넣을 수 없다. 다음 실질 작업은 작은 표적창의 공간·중복·연도·예산 검증과 수집 연결이다. 나지처럼 보이는 위치를 찾은 것과 구름 없는 동년6밴드 영상·최종 적격 패치를 확보한 것은 단계가 다르다.

## 담당과 보고

이번 collector 변경의 집중시험은7 PASS, 전체 백엔드는1,452건 중1,450 PASS/2 SKIP/실패0으로 완료했다. SKIP 두 건은 Windows 실제 심볼릭 링크 생성 권한 제한이다. 집중시험과 전체시험은 겹치므로 합산하지 않는다. 전체시험에는 임시·합성 자료 검증이 포함되며 실제 모델 과학성이나 운영 승인을 뜻하지 않는다. 실제 수집·고정 후보 QA·현재 브라우저 확인은 위의 별도 증거다.

- Root: 중복 작업 조정, 원본 보존, 단일 제한 실행, 회귀검증·Git·공통 인계.
- data_pipeline: 수집 중단 조사, 명시 재개 옵션·시험, 실행 전후 독립 관측.
- ml_pipeline: 실제 후보 QA 재검사와 bare 보완 후보·실행 공백 확인.
- web_ui: 147 커밋·소스 지문·현재 브라우저/서버 상태 교차 확인.
- understanding_agent: 완료된 코드와 관측을 읽고 쉬운 설명·대본·FAQ·INDEX·변경 이력 갱신.

기존10분 heartbeat `geoai-2`를 이 보고 채팅에 연결해 ACTIVE로 유지했다. 다음 보고에서도 예약 설정, 에이전트 실행, 수집 실행, 학습 실행을 따로 확인한다. 기존 두 미완료 작업을 복구 완료로 부르지 않으며 전체 개발은 계속 미완료다.

마감 중 다른 개발 채팅에서 부족 주·연도 우선 수집과 현황 UI를 개발하고 있음을 확인했다. 이를 중복 수행하지 않는다. 이번 시험을 마친 버전은 `codex/collection-resume-20261018`에 별도 기록하고, 이후 공유 작업폴더의 새 변경까지 시험을 통과했다고 확대하지 않는다. [152 표적 수집 RFC](152_targeted_bare_collection_rfc.md)는 다음 구현을 위한 설계이며 아직 수집 기능 구현 완료가 아니다.
