# 149. 학습자료 보완과 읽기 전용 재검사 — 2026-10-18

## 먼저 쉽게 설명

학습자료는 시험 문제집과 비슷하다. 사진이 1,000장 이상 있어도 같은 위성사진의 조각이 검증용과 시험용에 함께 들어가거나, 모델이 배워야 할 나지(풀·나무·건물이 없는 맨땅) 사례가 거의 없으면 준비 완료가 아니다. 총 장수, 서로 독립인 분할, 클래스 대표성, 동년 라벨, 구름·경계 품질을 각각 확인해야 한다.

이번 작업은 기존 자료를 바꾸지 않고 후보를 다시 검사하고 다음 보완 대상을 구체적으로 추리는 내부 작업이다. 원본 수집 재개·예산 정산·학습·모델 승인과 구분한다. 새 API나 화면을 바꾸지 않아 UI 변경은 필요 없다. 기존 화면의 저장 결과 조회와 새 증거 파일 생성도 구분한다.

## 이번에 구체화한 로컬 나지 검토 대상

고정 원본 1,384행의 `sample_class_coverage`를 읽어 ESRI 원분류8(모델 class7) 선언량이 256 이상인 패치를 찾았다. **훈련 2개·시험 1개, 총 3개가 있지만 모두 품질부적격**이다. 검증용 반텐에는 해당 선언량을 가진 패치가 없다. 적격 패치 중 나지 선언량의 최댓값은 학습240 / 검증84 / 시험184로 모두 256 미만이다.

- 남술라웨시 2022년: `south_sulawesi/00/r0-c2`, 선언 나지 545픽셀.
- 고론탈로 2024년: `gorontalo/01/r3-c0`, 선언 나지 271픽셀.
- 서자바 2020년: `west_java/v2-laneB-west_java-boundary-01/r3-c1`, 선언 나지 1,171픽셀.

새 `ml-resume-audit-20261018-bare-review-queue.json`에 원본 행 번호·scene·공간ID·기존 source window·동년 라벨과 다음 확인 조건을 담았다. 이 자료는 **저장된 약한 참조의 선별표**다. 최종 QA의 패치별 히스토그램이나 독립 현장 정답이 아니다. 품질 미달 패치를 적격으로 바꾸거나 문턱을 낮추지 않는다. 같은 해의 다른 관측시기에서 구름이 적은 영상을 찾을 가능성을 검토할 수 있지만, 새 scene이 나지 조건을 충족하는지는 아직 확인하지 않았다.

현재 수집 CLI에는 이 검토표를 바로 실행하거나 나지만 우선하는 job filter가 없다. 기존 lane-B 후보의 `expected_class_intent=bare`도 실제 나지 존재 증거가 아니다. 따라서 이 표를 실행 완료 config로 설명하면 안 된다. 검증용은 새로운 나지 공간을 별도로 찾는 단계가 필요하다.

### 반텐 확대 라벨에서 실제로 찾은 새 검토 위치

기존에 내려받은 반텐의 확대 ESRI 라벨17개를 실제로 읽고 원본 crop SHA를 전후 확인했다. 256×256 격자에서 원분류8이256픽셀 이상이고 공개 경계와의 기하 면적비가95% 이상인 창10개를 찾았다. 모두 기존 수집 영상창 밖에 있다. 위치·연도·픽셀수·고정 라벨SHA를 `ml-resume-audit-20261018-local-banten-label-search.json`에 기록했다. **VERIFIED_REAL(로컬 약한 라벨 바이트)**이며 나지의 현장 진실성이나 신규 Sentinel 품질은 미검증이다. 이10개는 연도별 창 수이며 독립 공간10곳 또는 적격 패치10개를 뜻하지 않는다.

여기서 실제 구현 공백도 확인했다. 이 작은 창을 중심으로 기존 수집 규격인1024×1024 창을 만들면10개 모두 기존 영상창과 겹친다. 기존 lane-B 검증기는 이런 중복을 거부한다. 따라서 바로 수집 가능한 새1024 후보는0개다. 작은256 타겟을 원본 정합·중복방지·공유예산·고정 split과 연결하는 지원을 추가하거나, 기존 창에서 더 먼 나지 위치를 찾아야 한다. 기존 중복방지 검사를 약화해 이10개를 실행하지 않는다.

## 지역·연도 보완과 동년·공간 분리

6개 주×2020~2025년 36칸에 모두 자료는 있지만, 칸당 28적격이라는 수집 계획 바닥까지 총 151개가 부족하다. 나지 부족과 별도의 편중 문제다. 예를 들어 남동술라웨시2024는1개로27개 부족하고, 고론탈로2025는8개로20개 부족하다. 후보에서 반텐2021은58→42로 줄지만28보다 높으므로 총 부족151은 동일하다. 이 계획 바닥은 학습 gate의 새 합격 기준을 발명한 것이 아니다.

동년 조건은 2024년 영상을 2024년 ESRI v003 참조와 대조하는 것이다. WC2021을 2024년 정답으로 복사하지 않는다. 동년이어도 ESRI는 약한 참조라 현장 조사·전문가 독립 검증을 대신하지 않는다.

공간 조건은 새 이름만 붙인 같은 위치를 새 표본으로 세지 않는다는 뜻이다. 고정 주별 4/1/1 분할, 원본 scene·source group·이미지 SHA 연결, 실제 bbox와 공간 위치를 다시 확인해야 한다. 같은 위치를 여러 해 반복해도 고유 공간 표본 여러 개로 세지 않는다.

저장 후보 QA의 훈련주 고유위치는 남술라웨시56·고론탈로64·남동술라웨시53·동자바44이고, 주별 적격수는216·154·127·131이다. 따라서 훈련주별 최소32위치·50패치 조건은 이미 충족한다. 현재 차단4건을 이 수량 조건 부족이라고 설명하지 않는다. 남는 핵심은 나지3조건이며 향후 신규 자료에서도 공간 독립성을 유지해야 한다.

## 이번 실제 실행과 근거

`evidence/integration/ml-resume-audit-20261018-runner.py`는 원본·정책·보존 readiness·staged candidate·과거 후보 QA를 외부 SHA로 먼저 고정한다. 기존 split validator에 실제 후보를 명시하고, bare 집계 진단 CLI를 새 evidence로 실행한다. 이후 `readiness.assess(..., connectivity_diagnostics=True)`만 직접 호출해 영상을 읽고 결과를 새 evidence에 기록한다. Dataset 준비·train·infer·Registry·수집 함수는 호출하지 않는다. PROJ network와 GDAL PAM 부수파일을 비활성화한다.

기존 run_experiment/73 CLI는 새 data 보고서를 만들기 때문에 이번 읽기 전용 재검사에는 사용하지 않았다. 순수 assess 호출과 새 evidence 결과를 73의 새로운 staged QA receipt 발행으로 오인하면 안 된다. 전체 반복 회귀가 아니라 변경 없는 실제 자료 재진단이며, 실행 완료 수치와 원장·lock 보존은 별도 summary 증거에 기록한다.

첫 실제 raster 재검사에서는 assess가 반환했지만, 뒤의 보호파일 SHA 대조에서 **원본 aggregate와 원장이 병렬 수집 재개에 의해 갱신되어 실패**했다. 새 readiness/성공summary는 저장 전이었으므로 생성되지 않았다. `ml-resume-audit-20261018-failed-stability.json`에 최초 pin·실패 후 pin·실패 위치를 보존했다. stale 원본을 성공으로 처리하지 않았다. Root의 명시 재개 collector가 새 batch 디렉터리와 aggregate·원장을 쓴 것과 이 읽기 전용 작업자의 쓰기0을 구분한다.

실제 assess의 입력은 고정 staged candidate와 정책이므로, 별도 `candidate-only-rerun.py`에서 이 두 파일·과거 후보QA·Root가 보존한 cdc 원본 사본을 고정하고 한 번 다시 검사한다. 현재 collector aggregate·원장은 전후 관측만 하며 이 **과거 고정1,095후보**의 입력이라고 부르지 않는다. 새 수집분을 반영한 새 후보 QA도 아니다. 반환값은 먼저 observation 파일로 보존하고 고정 입력의 최종 대조 결과를 별도 summary에 쓴다. 최초 실패를 삭제하거나 덮어쓰지 않는다.

상태: 최초 split/candidate 메타 재검증·bare 저장 산술은 당시 cdc 원본에서 실행 종료0. 고정1,095후보의 실제 raster 재검사는 **296.625초·종료0**, 2026-10-18 **10:01:19 KST** 완료다. `ml-resume-audit-20261018-candidate-only-summary.json`은 `FIXED_CANDIDATE_QA_REOBSERVED`, 적격628/217/250·차단4·ready=false를 기록한다. 고정4핀은 모두 안정했고 기존 QA와 status·차단·클래스 통계·정책·coverage·공간계수·4,285개 verified file 기록을 포함한13필드가 모두 일치한다. 현재 수집 aggregate·원장은 재검사 중에도 변경되었고 전후SHA를 별도 관측값으로 담았다. 이 결과를 새 수집분의 준비성으로 확대하지 않는다.

별도 `final-verifier.py`에서 새 QA가 기록한**4,285개 파일**의 SHA를 다시 실제로 계산하여 사후 보존도 확인했다. **28.188초·종료0·불일치0**, `FINAL_FROZEN_CANDIDATE_FILES_MATCH`다. 원래 readiness SHA도 유지된다. 결과는 `ml-resume-audit-20261018-final-verification.json`을 따른다. 순차 관측이므로 OS 원자 snapshot 보증은 아니다. **BLOCKED:** 학습·정식 모델 승인·독립 정답 검증. **PLANNED:** 위 검토표의 선택적 job 연결과 신규 나지 공간 확보. 이 작업자의 기존 원본·분할·모델·원장·lock 쓰기0.

## 다음 구현 가능한 작은 단위

1. 기존 수집 복구와 별개로, 검토표를 고정 SHA·고정 job ID에 연결하는 선택 계획을 만든다. 자동 다운로드 없이 dryrun에서 선택·제외 이유와 기존 성공창 중복을 검산한다.
2. 이번에 찾은 반텐의 작은256창10개는 기존1024창 중복을 일으키므로, 명시256 타겟 수집의 정합·예산·중복방지 계약을 별도 구현하거나 기존창에서 더 먼 나지 후보를 찾는다. 현장 진실성·영상 품질 미확인 상태를 유지한다.
3. 실행 권한·예산·미정산 작업 처리가 확정된 뒤 단일 coordinator의 명시 batch만 실행한다. 실제 품질·클래스·공간 QA와 1,000~3,000 상한을 통과한 새 후보를 발행한다.
4. 새 후보 전체 준비성을 재검사하고 기준을 모두 통과한 뒤에만 학습을 시작한다. 독립 평가·운영 승인은 별도로 진행한다.
