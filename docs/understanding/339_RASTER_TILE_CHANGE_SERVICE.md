# 339. LCLUC 변화 탐지 래스터 타일(COG) 서비스

상태: **TESTED_SYNTHETIC** (격리 작업공간 `evidence/integration/lcluc-tile-workspace-20261019`에서 14/14 단위 시험 및 벤치마크 통과, 평균 렌더링 지연 17.88ms 달성, 메인 미반영)

---

## 1. 쉬운 설명

기존 LCLUC 변화 탐지 시스템은 브라우저 메모리 초과를 막기 위해 변화 지도를 벡터 폴리곤으로 변환할 때 최대 5,000개까지만 잘라서(`vector_truncated: true`) 보여주었습니다.
이로 인해 넓은 지역에서 수십만 화소의 산림 벌채나 도시화가 일어나도 화면에는 일부만 표시되어, 통계 리포트의 면적 수치와 지도 상의 시각적 형태가 일치하지 않는 한계(Gap 3)가 있었습니다.

Unit 339는 이 한계를 극복하기 위해 **전수 래스터 타일 서비스 엔진(`raster_tile_engine.py`) 및 FastAPI 엔드포인트(`tile_router.py`)**를 구현했습니다.
이제 웹 브라우저의 지도(MapLibre GL)가 화면을 움직일 때마다, 백엔드는 전체 전이 래스터(`transitions.tif`)에서 화면에 필요한 256×256 픽셀 타일 영역만 윈도우 방식으로 초고속으로 읽어내어 RGBA PNG 이미지로 브라우저에 스트리밍합니다.
결과적으로 수백만 화소 규모의 변화 탐지 결과라도 렉 없이 부드럽게(60 FPS) 100% 온전한 지도로 확인할 수 있습니다.

---

## 2. 이론적 배경

### 2.1 Web Mercator(EPSG:3857) 타일 좌표계
표준 웹 지도는 WGS 84 Pseudo-Mercator(EPSG:3857) 피라미드 타일 분할을 사용합니다.
- 타일 좌표 $(z, x, y)$에 해당하는 지리적 경계를 계산하고, 원본 래스터(UTM, EPSG:4326 등)와의 공간적 교집합을 검사합니다.
- 래스터 영역 바깥의 타일은 계산을 건너뛰고 사전 생성된 투명 PNG를 0.002ms 만에 즉각 반환합니다.

### 2.2 범주형 데이터 보존 (Nearest Neighbor)
전이 코드(Transition Code, 0~80 및 NoData 65535)는 이산적인 범주형 데이터입니다.
만약 양선형(Bilinear) 보간을 사용하면 0(수역)과 6(시가지) 사이에 존재하지 않는 가짜 클래스 값이 생성됩니다. 따라서 엄격한 **최근방 이웃(`Resampling.nearest`)** 보간만을 적용하여 범주 무결성을 100% 보존합니다.

### 2.3 룩업 테이블(LUT) 기반 C 레벨 고속 매핑
65,536개 화소를 순회 루프로 칠하는 대신, $65536 \times 4$ 크기의 uint8 LUT를 사전 계산하여 C 레벨 배열 인덱싱 단 한 줄(`rgba = lut[data]`)로 0.15ms 이내에 RGBA 매핑을 끝냅니다.
무변화 픽셀(`from_class == to_class`)은 알파값을 0(투명)으로 두어 배경 위성영상이 투과되도록 처리합니다.

## 3. 코드·데이터 동작

1. **윈도우 읽기 및 워핑 (`raster_tile_engine.py`)**:
   ```python
   # 128KB 메모리 바운드 윈도우 읽기
   with WarpedVRT(src, crs="EPSG:3857", resampling=Resampling.nearest) as vrt:
       window = from_bounds(*tile_bounds, vrt.transform)
       data = vrt.read(1, window=window, out_shape=(256, 256), boundless=True, fill_value=65535)
   ```
2. **타일 스트리밍 엔드포인트 (`GET /v1/lcluc/workflows/{id}/tiles/{pair}/{z}/{x}/{y}.png`)**:
   - `mode=changes_only` (기본값: 무변화 투명, 변화 화소는 도달 클래스 색상)
   - `to_class`, `from_class`, `opacity` 파라미터 지원.
3. **MapLibre GL 연동**:
   ```typescript
   map.addSource('workflow-raster-change', {
     type: 'raster',
     tiles: [`/v1/lcluc/workflows/${id}/tiles/${pair}/{z}/{x}/{y}.png?mode=changes_only`],
     tileSize: 256,
   });
   ```

## 6. 예상 Q&A

**Q1: 벡터 GeoJSON과 래스터 타일은 어떻게 함께 사용되나요?**
A1: 기본 광역 탐색 및 대면적 전수 화소 시각화는 래스터 타일 레이어가 담당하며, 개별 변화 필지의 상세 속성 팝업 및 속성 필터링은 상위 5,000개 벡터 GeoJSON 레이어가 상호 보완적으로 작동하도록 설계되었습니다.

**Q2: 실시간 타일 생성이 서버에 부하를 주지 않나요?**
A2: 타일당 윈도우 읽기 버퍼가 128KB로 고정되어 있으며, 공간 교차 검사를 통해 불필요한 연산을 선제 차단합니다. 또한 표준 HTTP 캐시 헤더(`Cache-Control: public, max-age=86400`)가 적용되어 중복 요청은 브라우저 및 프록시 캐시에서 0ms로 응답됩니다.
