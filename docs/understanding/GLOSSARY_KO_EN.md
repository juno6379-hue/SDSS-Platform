## 5분·10분 읽는 법

5분은 AOI→STAC→COG→정합→readiness→Job/Result→SDSS 순서로 각 용어를 한 문장씩 설명한다. 10분은 scene 누출 사례, SHA의 한계, 의사라벨과 독립 정확도의 차이를 덧붙이고 [FAQ](presentations/FAQ.md)로 마무리한다. 이 표는 프로젝트 코드 해설이며 공식 표준 전체 정의를 새로 검증한 문헌 인용이 아니다.

## 차단 진단과 화면 반영 용어

| 용어 | 쉬운 뜻 | 이번 플랫폼에서의 주의점 |
|---|---|---|
| Local blocker | 해당 단계 자체의 차단 사유 | 입력·Agent 검사에서 나온 원인 |
| Upstream blocker | 실제 선행 단계의 차단 사유 | 의존 경로의 ancestor 중 local 원인이 있는 노드 |
| Policy blocker | 전체 중지 규칙으로 추가되는 사유 | FAIL_ALL의 다른 분기 원인; 실제 선행 원인과 별도 |
| STOP_DEPENDENTS | 의존하는 후속 단계만 중지하는 규칙 | 현재는 계획 원인 진단이며 실제 중지 실행 아님 |
| FAIL_ALL | 모든 분기에 중지를 적용하는 규칙 | 현재는 원인 범위 계산이며 실행 중 작업 취소 아님 |
| Submission snapshot | 접수 당시 검사 기록 | 같은 멱등 Job 재생은 최초 기록; 현재성 재인증 아님 |
| Plan request snapshot | 이번 계획 요청의 검사 기록 | Workflow는 매 요청 현재 자산을 다시 검사 |
| Build / Live UI | 배포용 코드 생성 / 현재 켜진 화면 | build 통과와 실행 서버·브라우저 반영은 각각 확인 |

실제 함수는 `workflow_policy.py:diagnose_workflow_blocking`, 응답은 `policy_resolution`과 `dependency_resolution`이다. 원인 없음 진단은 READY가 아니며 자료 무결성·기관 권한·과학 승인·실행 허가는 구분한다. 근거는 `docs/implementation/29_workflow_blocking_policy.md`와 `30_workflow_diagnostics_ui.md`다.

## 계보 검사 용어

- **Transitive lineage / 전이 계보**: 직접 부모뿐 아니라 그 위 조상까지 따라가는 출처 관계다. 이번 함수는 고정참조와현재파일을읽는내부코어다.
- **Diamond / 다이아몬드 경로**: 서로 다른 두 부모가 같은 조상을 공유하는 구조다. 같은자산은한번읽되더깊은경로의깊이한도는재검사한다.
- **Current assets revalidated / 현재 자산 검사 시도**: 응답필드true는resolve를한번이상시도했다는뜻이다. 모든조상의검사성공이나전체원자적snapshot은아니다.
- **Expanded / 부모 순회함**: 해당노드부모참조를순회했다는뜻이며상위모두의성공·운영승인은아니다.

`lineage_integrity_verified`와blocker를함께읽는다. 제한노드의더위계보는조회·출력하지않고권한/실행/과학승인은false다. 실제코드와한계는[데이터설명](01_DATA_PIPELINE.md)의계보절을따른다.

## 현재 계보 HTTP와 legacy 자료

- **Legacy catalog / 기존 자료목록**: 기존 `datasets`6행이다. 불변 `dataset_versions`의고정ID/version/자산SHA등록과다르며자동추정·등록하지않는다.
- **Read-only POST / 읽기진단POST**: 검사참조·한도를본문에받기위한요청이다. POST라고자료등록·학습/Job실행을수행하는것은아니다.
- **HTTP200 BLOCKED / 진단반환성공·검사차단**: 응답이반환됐다는뜻이며무결성통과가아니다.
- **no-store / 캐시저장금지**: 매요청현재자산검사를과거성공캐시로바꾸지않는다. 그래도여러파일의순차시점검사이며원자적snapshot은아니다.

계보API는현재를검사하고Job입력companion은과거제출기록을읽는다. 둘다권한·실행·과학승인과구분한다.

## Job의 현재 계보·부분 검사

- **Submission snapshot / 제출기록**: 당시 저장 점검표다. 없으면LEGACY지만 저장원요청이남아있을수있다.
- **Current Job lineage / Job 현재 계보**: 저장원요청의고정refs로지금파일을따라읽는별도진단이다. 과거snapshot을바꾸지않는다.
- **Binding checked / 입력 진단 수행**: 진단을수행/재사용했다는뜻이며성공이아니다. false는부분미검사·상충입력일수있다.
- **Reused / 요청내 재사용**: 같은고정root의진단cache다. 요청간과거성공을재생하지않고다른root공유조상검사비용은다시총예산에포함한다.
- **Available / 보고서 있음**: 현재보고서제공여부이며무결성통과나실행허가가아니다.

새GET companion은명시버튼으로만요청하고상태polling마다반복해시하지않는다. 부분검사와합산예산은[최신Gate](gate-notes/GATE_JOB_CURRENT_LINEAGE_20261017.md)를읽는다.

## Workflow 현재 계보·본문 신원

- **Raw request body SHA / 실제 전송본문 지문**: 서버가받은HTTPbytes의SHA다. UI는실제로보내는JSON.stringify(parsedPayload)의UTF8bytes를비교한다. canonical키정렬이나textarea들여쓰기원문hash와다르다.
- **Workflow shared diagnostic / 노드간 공유 진단**: 같은고정root를한요청에서한번검사하고노드들이같은diagnostic_index를쓴다. 요청간cache는없다.
- **DAG validated=false / DAG검증 미수행 가능**: 노드128상한에서DAG계산전종료할수있다. 순환이발견됐다는뜻으로단정하지않는다.
- **Inputs complete / 계보입력일치**: 개별계보의일치범위다. 모든노드가맞아도Workflow는PLAN_ONLY/BLOCKED이고URI·품질·Agent준비도·실행승인전체를검사하지않는다.

선행상한·부분예산·공유cache는[최신Gate](gate-notes/GATE_WORKFLOW_CURRENT_LINEAGE_20261017.md)를따른다.

## 카탈로그 메뉴와 복귀 용어

- **Utilization insight / 활용 인사이트**: 등록자료를입력·이용조건·메타품질·도구·공간관점에서검토하는5화면이다. 과학예측/준비완료판정이아니다.
- **Hash route / URL내 화면경로**: `#/catalog/insights/metadata?dataset=...`처럼화면과명시ID를기록한다. 직접진입/reload·back/forward를지원한다.
- **Session state / 탭내 복귀상태**: 검색초안/적용조건/체크ID와인사이트모델/참조지역을분리보관한다. 저장소차단시reload보존은보장하지않는다.
- **Latest rows resolution / 최신목록으로 상세찾기**: 옛Dataset객체대신ID로성공한최신Registry응답을확인한다. 없는ID를생성하거나추정하지않는다.
- **Navigation generation / 화면요청세대**: 시작URL과요청세대가맞는응답만표시해이전화면의늦은성공·오류가새화면에붙지않게한다. 서버작업취소기능은아니다.

명시상세ID또는유효한체크선택정확히1개는문맥으로만전달한다. Workspace열기와자동데이터주입/실행은다르다.

## 저장 split 계획 검증 용어

- **Caller-pinned inputs / 호출자 고정 입력**: 저장계획안의값을믿는대신별도로준source/readiness SHA·province split로다시계산한다.
- **Typed equality / 타입까지 같은 문서**: true/1·1/1.0과배열순서/키집합을구분한다. 중복키·NaN/Infinity·미지필드변조를거부한다.
- **NOT_REQUESTED/null / 검사 미요청**: 후보옵션을주지않았다는뜻이며후보존재/부재·성공/실패의판정이아니다.
- **METADATA_INTEGRITY_VERIFIED / 계획문서 무결성 일치**: 재계산계획이맞는범위이며실제raster·공간·클래스준비도나과학/학습승인이아니다.
- **CP949 console / Windows 콘솔 인코딩**: UTF8evidence저장과stdout출력의성공은다르다. 최종CLI는ASCIIescape콘솔출력으로exit0을확인했다.

계획예상1,095와실제원본1,111을구분하고후보발행·학습으로확대해석하지않는다.

## 수집 terminal·정산 용어

- **Raw config digest / 변환 전 config 지문**: 원장과비교하는정렬JSON문서digest다. 파일원시bytesSHA나WorkflowHTTP본문SHA와다르다.
- **Normalized config digest / 정규화 config 지문**: years를periods로명시변환한뒤window-state와비교하는digest다. raw지문과같아야하는것은아니다.
- **Terminal artifact / 작업 종료 보고자료**: worker-result/source report등이다. 존재하거나JSON형태라는사실만으로작업완료·전송계측·정산승인이확정되지않는다.
- **CONSISTENT_METADATA / 검사한 메타 일치**: 검사필드에모순없음이다. source-report암호학적신원·완전전송·프로세스종료·정확히한번aggregate반영과별개이며계속BLOCKED다.
- **Upper−measured / 상한과 계측 차이**: 미계측/예약차이표시다. 실제환불가능액으로읽지않는다.
- **Exactly-once aggregate / 정확히 한 번 반영**: 중복/누락없이집계됐는지의별도증거다. 이번inspector는UNKNOWN을유지하고원장을정산하지않는다.

CLI exit0은읽기조사/보고성공이며실제복구·재시작허가가아니다.

## Aggregate 대조 용어

- **Aggregate / 합산 명세**: 여러source report에서만든patch목록이다.1,384명세행조회가raster1,384파일재검사는아니다.
- **Two-field metadata link / 두 필드 메타 연결**: (source_window.path,scene_id)쌍을원천row와대조한다. year/province·cropwindow·raster내용신원은미검사다.
- **Canonical path / 해석한 표준 경로**: 참조별alias를정리해중복/범위/target변경을찾는다. raster파일의존재/내용/SHA를인증하지않는다.
- **Reverse reconciliation / 역방향 대조**: 원장report가합산목록에있는지만아니라목록의참조가원장한건에연결되는지도검사한다. unknown/ambiguous를구별한다.
- **OUT_OF_SCOPE / 현재 집계 범위 밖**: 다른실험output은현재aggregate누락으로세지않는다. 범위를모르는경우를자동으로제외하는뜻은아니다.
- **Patch duplicate / 패치 식별 중복**: patchID/이미지경로중복이다. 같은촬영scene의여러crop은정상이며이검사만으로물리crop·평가split누출을판정하지않는다.

CONSISTENT_METADATA/issues0은정확히한번정산·반영의journal증명이아니고statusBLOCKED/승인false를유지한다.
